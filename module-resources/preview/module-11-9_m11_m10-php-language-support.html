The security lecture explains which property a value needs: confidentiality, integrity, or authentication. This page explains how to read the PHP calls that implement those choices. The examples use fictional equipment labels rather than the assignment's tax-identifier migration.

A function name is not enough to explain a control. Follow its arguments, returned value, failure result, and the next statement that uses that result. The course helpers make cryptographic operations available without requiring you to design a cryptographic algorithm.

iUse learning data and keep keys out of evidence

These exercises use invented text and temporary generated keys, because reports and screenshots may circulate beyond the lab. Do not replace a fixture with real personal data or print a real application key.

1PHP strings can contain text or binary bytes

A PHP string holds bytes. It can contain visible characters, random bytes, or ciphertext. strlen counts bytes rather than user-perceived characters. bin2hex and base64 encode bytes into printable text; they do not encrypt them.

PHP
<?php
$value = 'kit-7';
$encoded = base64_encode($value);
echo $encoded . "\n";
echo base64_decode($encoded, true) . "\n";
echo strlen($value) . "\n";
Output
a2l0LTc=
kit-7
5

The encoded result can be decoded without a key. The second argument true requests strict decoding, which can return false for invalid input. A caller must distinguish that failure from a valid decoded string.

★Representation and protection are separate decisions

Base64 makes bytes convenient to store or transmit as text. Anyone with that text can decode it. Confidentiality requires an encryption operation and controlled access to its key.

Source: PHP base64_encode (opens in a new tab) and PHP base64_decode (opens in a new tab) describe the representations and strict failure result.

2Read constants, arguments, and an authenticated round trip

This standalone example requires the PHP sodium extension. It generates a temporary key in memory and prints only observable results, never the key, nonce, or ciphertext.

✓PHPSecure
<?php
// WHY: Authenticated encryption checks both the ciphertext and its associated record context before returning plaintext.
$key = sodium_crypto_aead_xchacha20poly1305_ietf_keygen();
$nonce = random_bytes(SODIUM_CRYPTO_AEAD_XCHACHA20POLY1305_IETF_NPUBBYTES);
$plaintext = 'Loan kit';
$context = 'equipment-7';
$ciphertext = sodium_crypto_aead_xchacha20poly1305_ietf_encrypt(
    $plaintext, $context, $nonce, $key
);
$opened = sodium_crypto_aead_xchacha20poly1305_ietf_decrypt(
    $ciphertext, $context, $nonce, $key
);
echo strlen($plaintext) . "\n";
echo strlen($ciphertext) . "\n";
echo $opened . "\n";
var_dump(sodium_crypto_aead_xchacha20poly1305_ietf_decrypt(
    $ciphertext, 'equipment-8', $nonce, $key
));

Secure. Why: Authenticated encryption checks both the ciphertext and its associated record context before returning plaintext.

Output
8
24
Loan kit
bool(false)

The uppercase name beginning SODIUM_ is a constant provided by the extension. It gives the required nonce length, 24 bytes for this primitive. The temporary key is 32 bytes. The ciphertext includes a 16-byte authentication tag, so its length here is 8 plus 16.

Read the encrypt call's arguments in order: plaintext, associated data, nonce, key. Associated data is authenticated without being encrypted. Decryption needs the same values for associated data, nonce, and key. Using a different equipment context makes authentication fail even though the ciphertext itself is unchanged.

var_dump displays both type and value, so the failure is shown as bool(false). That differs from an empty string, which could be a valid plaintext. The output's predictable lengths and round-trip result can be checked; the randomly generated bytes will vary.

Source: PHP sodium encryption (opens in a new tab) and PHP sodium decryption (opens in a new tab) document these arguments and results.

The course's lib/crypto.php defines functions that wrap authenticated encryption. They are application helpers rather than PHP built-ins.

The format is v1.nonce.ciphertext, with the nonce and ciphertext represented as base64 text. ENC_VERSION is a constant defined in the helper. explode('.', $sealed, 3) splits the storage string into at most three parts. count checks how many parts were obtained, and $parts[0] selects the first.

The helper converts the cryptographic false failure into null with a conditional expression: $plain === false ? null : $plain. A caller must handle that no-plaintext result without treating it as decrypted data.

!Nullable return is not a complete error boundary

Handle both rejected ciphertext and thrown errors at the appropriate application boundary, because a malformed base64 component can throw before the helper reaches its final return. The current helper's header comment describes malformed input broadly; reading its implementation reveals this distinction.

When the lecture uses (string) $row['id'], the cast represents the record id as a string for associated data. It does not authenticate the id or check object permission. Use the same stable context when sealing and opening because changing it intentionally prevents a successful open.

These contracts were checked against the supplied helper implementation. Changing a helper's implementation later requires checking its callers again.

4Read environment access and exceptions

getenv('TECHCORP_DATA_KEY') reads an environment variable; it does not read a .env file automatically. A launcher or application configuration mechanism must load that file into the process environment where PHP runs.

getenv returns a string or false. The helper's ?: '' uses an empty string when the retrieved value is falsy. Its explicit key-length test then refuses invalid configuration.

throw new RuntimeException(...) constructs an exception and interrupts normal execution. A matching catch can handle it. This standalone example models a missing configuration without touching your real environment.

✓PHPSecure
<?php
// WHY: Invalid configuration follows a controlled branch instead of allowing an operation with an absent key.
try {
    $configuredKey = '';
    if ($configuredKey === '') {
        throw new RuntimeException('Missing learning configuration');
    }
    echo "Operation continued.\n";
} catch (Throwable $error) {
    echo "Configuration rejected.\n";
}

Secure. Why: Invalid configuration follows a controlled branch instead of allowing an operation with an absent key.

Output
Configuration rejected.

The line after throw is not reached. The catch variable holds the error object, but this example prints no exception detail. A production response needs the course's safe error handling rather than exposing a key, trace, or internal configuration path.

Source: PHP getenv (opens in a new tab) documents environment retrieval; PHP Throwable (opens in a new tab) describes the shared interface used by exceptions and errors.

5Read HMAC calls without confusing them with encryption

hash_hmac('sha256', $value, $key) produces a keyed authentication tag. It does not hide the value. This standalone example generates a temporary key and compares results without printing the key or tag.

✓PHPSecure
<?php
// WHY: Recomputing the tag over the received value detects a changed value under the same key.
$key = random_bytes(32);
$value = 'equipment-7';
$tag = hash_hmac('sha256', $value, $key);
$received = 'equipment-7';
echo strlen($tag) . "\n";
echo hash_equals($tag, hash_hmac('sha256', $received, $key)) ? "Verified\n" : "Rejected\n";
$received = 'equipment-8';
echo hash_equals($tag, hash_hmac('sha256', $received, $key)) ? "Verified\n" : "Rejected\n";

Secure. Why: Recomputing the tag over the received value detects a changed value under the same key.

Output
64
Verified
Rejected

The default tag representation is hexadecimal text. SHA-256 produces 32 bytes, represented here by 64 characters. hash_equals compares strings deliberately; it does not hash them. Its first argument is the known expected value. Unequal lengths return false immediately, so its timing-aware comparison does not hide the expected length.

In lib/hmac.php, hmac_sign($value) returns value.signature. hmac_verify($signed) returns the original value or null, and can throw when the signing configuration is invalid. strrpos($signed, '.') locates the last separator. It returns an integer position or false, which is why the helper checks === false. A separator at position zero is an integer zero, not the Boolean false.

substr($signed, 0, $dot) selects the value before the separator. substr($signed, $dot + 1) selects the signature after it. The helper recomputes the tag and compares it. Verification provides no expiration, replay prevention, or object authorization on its own.

Source: PHP hash_hmac (opens in a new tab) documents tag generation; PHP strrpos (opens in a new tab) documents positions and its failure result.

6Read iteration and version checks in a migration

foreach ($rows as $row) runs a block once for each row. str_starts_with($stored, 'v1.') tests a prefix. continue skips the remaining statements in the current iteration and advances to the next row.

A version prefix helps select which processing path to attempt. It does not authenticate a storage string. A value beginning v1. can still be malformed or tampered with. Treating it as already processed is a migration decision that needs verification rather than proof that its contents open successfully.

The course query helper's parameter array supplies values in placeholder order. Updating a record with a sealed value changes storage; selecting and opening it later changes representation for a permitted use. Those are different operations, and a storage migration needs its own verification and recovery plan.

Source: PHP str_starts_with (opens in a new tab) defines the prefix test.

7Read byte modifications and signature functions

The lecture changes a ciphertext byte to demonstrate failed authentication. $ciphertext[0] selects a one-byte string. ord obtains that byte's number; ^ is bitwise XOR; chr turns the changed number back into a one-byte string. This is a test of altered data, not a repair operation.

Digital-signature calls use a different key arrangement. sodium_crypto_sign_keypair creates a key-pair representation. Functions extract its secret signing key and public verification key. sodium_crypto_sign_detached returns a signature separate from the message. Verification returns a Boolean indicating whether the signature matches the message under the public key. A signature does not encrypt the message.

When a function produces random bytes, key pairs, or ciphertext, expected evidence can state properties such as a successful round trip or failed verification without promising exact random output bytes.

Source: PHP detached signature verification (opens in a new tab) describes the verification result.

9Check your reading

9. Check your reading. Columns: Question, Answer and explanation.

Does base64 require a secret key?No. It is a reversible representation.
What does strlen count?Bytes in the PHP string, not necessarily visible characters.
What does the sodium nonce constant supply?The required byte length for that primitive's nonce.
Is associated data hidden by encryption?No. It is authenticated as context without being encrypted.
Is false the same as an empty plaintext string?No. Use a strict failure check before treating a result as plaintext.
Does ?string rule out exceptions?No. It describes permitted normal return values.
Does getenv load a .env file?No. Another mechanism must load that configuration into the environment.
