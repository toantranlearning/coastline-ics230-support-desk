Requests and Developer Tools

This page shows the two ways you look at what the portal really sends and receives: curl in the Cloud Shell terminal, and the developer tools built into your browser. Assignments say "send the request" or "read the response headers" and point here for how.

Sending a request with curl

curl is a command that sends one HTTP request and prints what comes back. It runs in the Cloud Shell terminal, and the portal is at http://localhost:8080 from there. Every example below assumes the portal is running (bash scripts/start.sh if it is not).

A GET request, with the headers

  1. In the terminal, type the command and press Enter: ``bash curl -i http://localhost:8080/login.php ``
  2. You will see the status line, the headers, a blank line, then the page's HTML: ``text HTTP/1.1 200 OK Host: localhost:8080 Date: Thu, 08 Oct 2026 16:09:30 GMT Connection: close Set-Cookie: PHPSESSID=a7093f9d7ecb027c2cc7ddcd26eed17a; path=/ Cache-Control: no-store, no-cache, must-revalidate <!doctype html> ... ``

-i means include the response headers in the output. Without it you get only the body. The first line is the status: 200 OK means the page was served. Set-Cookie is the server handing your client a session cookie. The Date line and a X-Powered-By line will show your own values.

A POST request that submits a form

A sign-in is a POST. -d sends the data as the request body, the way a browser form does, and -c saves any cookie the server sets to a file so the next request can send it back.

  1. Send the sign-in: ``bash curl -i -c jar.txt -d 'username=rmarsh&password=password' http://localhost:8080/login.php ``
  2. You will see a redirect, which is what a successful sign-in returns: ``text HTTP/1.1 302 Found Set-Cookie: PHPSESSID=ceaccdfc4c98c421948ebe0e8ea6f9fe; path=/ Location: index.php ``
  3. Send the saved cookie with the next request, using -b: ``bash curl -b jar.txt 'http://localhost:8080/customer.php?q=Test' ` Put a URL that contains ? or &` in single quotes, or the shell reads those characters itself.

A POST request with a JSON body

An API takes JSON, not a form. Three options build the request: -X POST sets the method, -H adds a header, and -d carries the body.

Bash
curl -i -X POST -H 'Content-Type: application/json' -d '{"name":"Alma"}' http://localhost:8080/api/customers

Until an endpoint exists at that address the router answers:

HTTP/1.1 404 Not Found
Content-Type: application/json

{"error":"No such resource"}

A body that is not valid JSON is sent the same way; what you are testing is how the server answers it:

Bash
curl -i -X POST -H 'Content-Type: application/json' -d '{"name":' http://localhost:8080/api/customers

Saving a response to a file

-o writes the body to a file instead of the screen, which is how you download a library file to hash it:

Bash
curl -s -o flatpickr.min.js https://cdn.jsdelivr.net/npm/flatpickr@4.6.13/dist/flatpickr.min.js

Reading what you got

Reading what you got. Columns: You see, It means.
You seeIt means
200 OKThe request succeeded and the body is the result
302 Found with a Location headerThe server is sending you somewhere else; a browser would follow it
400 Bad RequestThe server refused the request itself, usually a validation failure
401 UnauthorizedNo valid credential came with the request
403 ForbiddenThe credential is valid and this action is not allowed
404 Not FoundNothing is at that address
429 Too Many RequestsA rate limit stopped the request

Paste the command and the response, as text, into your report's evidence section. Trim the body to the lines that show the result.

The browser's developer tools

Developer tools show the same requests the browser makes on your behalf, with their headers, and the cookies it holds. Open the portal in the Web Preview tab, then press F12, or Ctrl+Shift+J (Cmd+Option+J on a Mac).

Reading a request and its response: the Network panel

  1. Click the Network tab. The panel records only while it is open, so open it before you do the thing you want to see.
  2. Do the action in the page: submit the form, click the link.
  3. A row appears for each request. Click the one you want (the page's own name, such as notes.php).
  4. The Headers tab shows the request method, the status code, the request headers the browser sent, including Cookie, and the response headers the server returned, including Set-Cookie and any security headers.
  5. The Response tab shows the body the server sent, before the browser rendered it.

To compare two requests, do the action twice and click each row in turn. The request headers are what the server actually received, which is the evidence an assignment asks for.

Reading errors the browser reports: the Console panel

Click the Console tab. The browser prints there anything it refused or could not load, with the reason: a script whose integrity check failed, a request a security policy blocked, a JavaScript error. Reload the page with the panel open to see the messages for that load.

Viewing and editing a cookie: the Application panel

  1. Click the Application tab, then Storage, then Cookies, then the portal's address.
  2. Each cookie is a row: name, value, and its attributes (Domain, Path, Expires, HttpOnly, Secure, SameSite).
  3. To change a value, double-click the Value cell, type the new value, and press Enter. The next request the browser sends carries the changed cookie. Reload the page to see the effect.

A cookie you can edit here is a cookie the server cannot trust; that is the point of the exercise when an assignment asks you to try it.

Troubleshooting

  • curl: (7) Failed to connect. The portal is not running. Run bash scripts/start.sh and try again.
  • The response is a sign-in page when you expected data. The request carried no session cookie. Sign in with -c jar.txt first, then send -b jar.txt with the request.
  • The shell complains about ? or &. Put the whole URL in single quotes.
  • The Network panel is empty. It was opened after the request. Keep it open and do the action again.
  • You edited a cookie and nothing changed. Reload the page; the change rides on the next request.

Sources: curl manual page (opens in a new tab) for every option above; Chrome DevTools: Inspect network activity (opens in a new tab) and Chrome DevTools: View, add, edit, and delete cookies (opens in a new tab) for the two panels. Firefox and Edge have the same panels under the same names.
