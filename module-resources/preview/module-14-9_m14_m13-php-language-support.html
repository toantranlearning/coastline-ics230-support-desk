The security lecture explains browser policy and file handling. This page explains the PHP statements used to express those controls: header strings, upload arrays, constants, file inspection, generated names, and download responses. Its examples use fictional equipment diagrams rather than the assignment's document-upload repair.

A complete upload handler also needs authentication, authorization, CSRF protection where appropriate, size limits, safe storage, and controlled errors. These language examples explain individual statements without adding new graded requirements.

1Build a response-header string

header sends an HTTP response header. Its argument is a PHP string containing the header name, a colon, and the value. Output must not have committed the headers yet.

The following standalone program constructs a header string and prints it as text. It does not send an HTTP response.

PHP
<?php
$directives = [
    "default-src 'self'",
    "object-src 'none'",
    "frame-ancestors 'none'",
];
$policy = implode('; ', $directives);
echo 'Content-Security-Policy: ' . $policy . "\n";
Output
Content-Security-Policy: default-src 'self'; object-src 'none'; frame-ancestors 'none'

The array contains three strings. implode('; ', $directives) joins them with semicolon-space separators. The period concatenates the header name with the resulting policy. Single quotes inside each double-quoted PHP string belong to the CSP value.

To send the constructed string in a web handler, the corresponding operation is header('Content-Security-Policy: ' . $policy);. Sending a policy can affect which resources the browser loads. A syntactically valid string can still express the wrong application policy.

!Compare policy with actual page behavior

Check legitimate scripts, styles, images, and framing needs after a policy change, because a restrictive header can block required resources as well as unwanted ones. The response header and browser behavior are separate pieces of evidence.

Source: PHP header (opens in a new tab) describes sending headers; PHP implode (opens in a new tab) describes joining array values.

2Read nonce generation and interpolation

The lecture generates a nonce with base64_encode(random_bytes(16)). The bytes are random; base64 represents them as printable text. A double-quoted PHP string can substitute the value of a variable into the text.

✓PHPSecure
<?php
// WHY: A fresh nonce identifies the script elements this response deliberately permits.
$nonce = base64_encode(random_bytes(16));
$policy = "script-src 'nonce-$nonce'";
echo strlen($nonce) . "\n";
echo str_starts_with($policy, "script-src 'nonce-") ? "Nonce directive built.\n" : "Unexpected directive.\n";

Secure. Why: A fresh nonce identifies the script elements this response deliberately permits.

Output
24
Nonce directive built.

Sixteen bytes produce 24 base64 characters including padding. The nonce and policy vary, so this exercise prints only predictable properties. In the actual web response, the policy's nonce must match the permitted script element's nonce attribute. A static nonce copied across responses does not provide the intended unpredictability.

Source: PHP random_bytes (opens in a new tab) describes random byte generation.

3Read the upload array without trusting its labels

For a multipart upload whose form field is diagram, PHP places upload information in $_FILES['diagram']. $_FILES is an array, and each entry contains further named values.

3. Read the upload array without trusting its labels. Columns: Entry, What it means.
EntryWhat it means
nameThe client-supplied filename
typeThe client-declared media type; it is not server verification
tmp_namePHP's temporary path for the received upload
errorAn integer upload error code
sizeThe received file size reported in bytes

A form field can also be structured as an array, so assumptions about each entry's shape require checking. UPLOAD_ERR_OK is an integer constant meaning that PHP reported no upload error. It does not mean the file's content is permitted or harmless.

This standalone exercise models metadata without uploading a file.

✓PHPSecure
<?php
// WHY: Shape and error checks reject missing or unexpected metadata before later file operations.
$upload = ['error' => UPLOAD_ERR_OK, 'size' => 1200];
if (!isset($upload['error']) || !is_int($upload['error']) || $upload['error'] !== UPLOAD_ERR_OK) {
    echo "Upload rejected.\n";
} elseif (!isset($upload['size']) || !is_int($upload['size']) || $upload['size'] > 1024 * 1024) {
    echo "Size rejected.\n";
} else {
    echo "Metadata checks passed.\n";
}

Secure. Why: Shape and error checks reject missing or unexpected metadata before later file operations.

Output
Metadata checks passed.

|| means logical OR. Short-circuit evaluation skips later operands when an earlier one is true. elseif tests another condition only when the first branch did not run. 1024 * 1024 is multiplication, giving 1,048,576 bytes for this example's limit. Passing these checks establishes only those metadata conditions.

Source: PHP POST uploads (opens in a new tab) explains the entries; PHP upload errors (opens in a new tab) defines the error codes.

4Read a file-inspection object and allow-list

new finfo(FILEINFO_MIME_TYPE) constructs an object configured to identify media types from file content. $inspector->file($temporaryPath) calls that object's method. The result can be a media-type string or false.

This fragment needs an actual allowed temporary upload and is not standalone.

✓PHPSecure
<?php
// WHY: A detected type is mapped to a server-chosen extension rather than trusting the uploaded filename.
$inspector = new finfo(FILEINFO_MIME_TYPE);
$detected = $inspector->file($temporaryPath);
$allowed = ['image/png' => 'png'];
if (!is_string($detected) || !isset($allowed[$detected])) {
    http_response_code(415);
    exit('Unsupported file type');
}
$extension = $allowed[$detected];

Secure. Why: A detected type is mapped to a server-chosen extension rather than trusting the uploaded filename.

The map's key is a detected media type; its value is the stored extension selected by the application. $allowed[$detected] retrieves the extension for a permitted type. The string check prevents a detection-failure result from being used as a valid media type.

Content-based detection is useful evidence about a file format. It does not establish that a file has no malicious content, that a complex parser can process it safely, or that it cannot contain multiple interpretations. The storage and serving controls remain necessary.

Source: PHP finfo_file (opens in a new tab) documents the inspection result.

5Read generated names and file-operation results

bin2hex(random_bytes(16)) . '.png' creates an application-chosen basename. The extension comes from the permitted type map, and the received name is excluded from the stored path.

__DIR__ is the current PHP file's directory. dirname(__DIR__) selects its parent. String concatenation constructs a path but does not determine whether that location is outside the server's served root; that depends on the actual deployment.

move_uploaded_file($temporaryPath, $destination) returns a Boolean. It checks whether the source is a valid PHP HTTP upload and moves it to the specified destination. A move can fail because of permissions, a missing directory, or another filesystem problem. It can overwrite an existing destination, so generated names and collision handling still matter.

mkdir creates a directory and returns a Boolean. Directory preparation needs controlled permissions and error handling. rename moves or renames a filesystem entry; it does not provide move_uploaded_file's HTTP-upload source check. Neither function inspects or sanitizes file contents.

✓Check the operation's result before recording success

Treat a failed move as a failed storage operation, because a database entry claiming the file was saved can point to a nonexistent file. File movement and metadata storage require a deliberate failure and recovery plan.

Source: PHP move_uploaded_file (opens in a new tab), PHP mkdir (opens in a new tab), and PHP rename (opens in a new tab) define these separate operations.

6Read a controlled download response

The lecture's download handler looks up a stored record, checks the caller, and only then sends the file. A prepared query controls SQL interpretation; an ownership or role check controls access. q_one is a course helper returning an associative row or null.

filesize($path) returns the file's byte size or false on failure. readfile($path) writes the file's bytes to the output and returns the number of bytes read or false. A path must come from controlled storage metadata rather than an arbitrary requester-supplied location.

Content-Type names the approved media type. Content-Disposition: attachment requests download handling. A server-generated filename prevents requester-supplied characters from entering the header. X-Content-Type-Options: nosniff tells the browser to respect the declared type in applicable contexts. These headers do not establish object authorization.

Sending JSON errors uses json_encode(['error' => 'not_found'], JSON_THROW_ON_ERROR) rather than concatenating untrusted values into JSON text. An error response must be selected before file output starts: writing half a file and then appending an error body produces an inconsistent response.

★Reading bytes is an output operation

readfile does not execute PHP code in the file. A direct URL served by a PHP-enabled web server can take a different path and execute a script. Storage outside the served root and a controlled download route prevent that alternate serving path.

Source: PHP readfile (opens in a new tab) describes byte output; PHP filesize (opens in a new tab) describes size and failure results.

8Check your reading

8. Check your reading. Columns: Question, Answer and explanation.
QuestionAnswer and explanation
What does implode do in the header example?Joins directive strings with the chosen separator. It does not validate the resulting policy.
Does echo send a CSP header?No. It writes response text. header sends the header.
Why is a nonce output not fixed?It uses newly generated random bytes.
Is the upload's type entry verified by PHP?No. It is client-supplied metadata.
What does UPLOAD_ERR_OK establish?PHP reported no upload error, not that the content is safe.
What does ->file mean?A method call on the finfo object to inspect a specified file.
What does the media-type map return?A server-selected extension for an allowed detected type.
Does rename verify an HTTP-upload source?No. That check is provided by move_uploaded_file.
Can moving an upload fail?Yes. Check its Boolean result before reporting success.
Does readfile execute PHP code in the file?No. It outputs file bytes. A direct server-serving route can behave differently.
Does an attachment header authorize a download?No. Permission must be checked before serving the file.
Does valid metadata prove a harmless file?No. It proves only the checks actually performed.
