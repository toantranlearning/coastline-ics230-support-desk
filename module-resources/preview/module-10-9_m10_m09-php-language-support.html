A training inventory application receives a password, checks the stored credential, and starts an authenticated session. On the next request, the password is absent; a cookie identifies the session instead. Reading those two paths requires recognizing which PHP operations return a value, which change stored state, and which stop the request.

The security lecture teaches authentication, password storage, throttling, session lifecycle, and MFA. This companion explains the PHP used to implement those controls. Its inventory examples are separate from the incident assignment's sign-in repair.

★A function call can return a value and change state

password_verify returns a Boolean. session_regenerate_id returns a Boolean and changes the active session identifier. A query helper can return rows or change the database. Read both the returned result and the operation's side effects.

1Read the submitted field without assuming its type

PHP fills $_POST with submitted form fields. An associative array uses named keys such as password; square brackets select an entry. The null coalescing operator ?? supplies a default when an entry is missing or null.

✓PHPSecure
<?php
// WHY: A supplied array is not a password string; checking the type avoids passing it to a string operation.
$fields = ['password' => ['unexpected']];
$password = $fields['password'] ?? null;
if (!is_string($password)) {
    echo "Expected a password string.\n";
} else {
    echo "Password field has the expected type.\n";
}

Secure. Why: A supplied array is not a password string; checking the type avoids passing it to a string operation.

Output
Expected a password string.

is_string returns true for text and false for other types. The ! reverses that Boolean. Braces enclose the statements run by the selected branch. In a real handler the first array is $_POST; this standalone example supplies a simulated field so you can observe the wrong-type path.

Question: Does ?? '' prove the field is text? No. It supplies an empty string only when the field is missing or null. An array supplied under that key remains an array.

Question: Should a password be trimmed? Usually no. Spaces can be intentional password characters. A username may have a documented normalization rule, but that does not authorize silently changing a password.

Source: PHP null coalescing operator (opens in a new tab) explains how the default is selected.

2Distinguish assignment, comparison, and short-circuiting

= stores a value. === compares value and type. !== asks whether they differ in value or type. && means both conditions must be true; || means at least one must be true. PHP evaluates these logical operators from left to right and can skip the right operand when the left already determines the answer.

PHP
<?php
$row = null;
if ($row === null || $row['enabled'] !== 1) {
    echo "Access check failed.\n";
}
$matched = true;
var_dump($matched && $row !== null);
Output
Access check failed.
bool(false)

The first condition checks for a missing row. Because that is true, PHP skips the array lookup on the right. The final expression is false because the row is null, even though $matched is true. In the lecture, a dummy password hash can match a supplied password without granting access: the account must also exist.

!A Boolean result must control the branch

Calling a verification function and ignoring its return value does not enforce authentication. Place access-granting statements only on the successful branch because the call can return false.

Source: PHP logical operators (opens in a new tab) documents &&, ||, and short-circuit evaluation.

3Hash a password and verify the result

password_hash($password, PASSWORD_DEFAULT) accepts the password string and an algorithm selector. It returns a self-describing hash string containing the algorithm, settings, and generated salt. PASSWORD_DEFAULT is a named constant, not a quoted word. The constant is designed to change as supported defaults evolve.

password_verify($typed, $stored) takes the submitted password first and the stored hash second. It returns true on a match and false otherwise.

✓PHPSecure
<?php
// WHY: The adaptive hash protects stored passwords without providing a way to decrypt them.
$stored = password_hash('Inventory demo passphrase', PASSWORD_DEFAULT);
var_dump(password_verify('Inventory demo passphrase', $stored));
var_dump(password_verify('Different passphrase', $stored));

Secure. Why: The adaptive hash protects stored passwords without providing a way to decrypt them.

Output
bool(true)
bool(false)

The hash itself is deliberately not shown as fixed output: its random salt makes a new hash differ each time. Two calls can return different strings that both verify the same password. Store the complete returned string, rather than cutting it to the length of today's format.

password_hash can throw an exception when an algorithm or required operation fails. Authentication code must not continue as though a hash had been created. The portal's pw_hash wrapper also returns a hash or throws; it does not return a usable fallback password.

Question: Why not compare two new password_hash results with ===? Their random salts differ. Use password_verify against the stored hash.

Question: Does PASSWORD_DEFAULT satisfy every password policy automatically? No. Algorithm limits and policy must agree. Bcrypt's 72-byte limit matters for long Unicode passwords; the security lecture explains the design choice.

Sources: PHP password_hash (opens in a new tab) and PHP password_verify (opens in a new tab) define these argument and return contracts.

4Ask whether a verified hash needs upgrading

password_needs_rehash($stored, $algorithm, $options) inspects a stored hash's algorithm and settings. Its Boolean result does not establish whether a submitted password is correct. Verification is a separate operation.

✓PHPSecure
<?php
// WHY: Rehash only a verified password so an incorrect submission cannot overwrite the credential.
$typed = 'Inventory demo passphrase';
$stored = password_hash($typed, PASSWORD_BCRYPT, ['cost' => 10]);
if (password_verify($typed, $stored)) {
    if (password_needs_rehash($stored, PASSWORD_BCRYPT, ['cost' => 12])) {
        $stored = password_hash($typed, PASSWORD_BCRYPT, ['cost' => 12]);
        echo "Verified hash upgraded.\n";
    }
}
var_dump(password_needs_rehash($stored, PASSWORD_BCRYPT, ['cost' => 12]));

Secure. Why: Rehash only a verified password so an incorrect submission cannot overwrite the credential.

Output
Verified hash upgraded.
bool(false)

['cost' => 10] is an options array with one named key. Nested if blocks mean the upgrade runs only after verification succeeds. This example changes a variable; a web application must also persist the new hash using its database helper.

The course wrappers use the configured defaults: pw_hash($password) creates a hash; pw_verify($password, $stored) checks it; pw_needs_rehash($stored) asks whether it needs updating. require_once __DIR__ . '/lib/passwords.php'; loads their definitions once. __DIR__ is the directory of the current PHP file, and . joins strings into the path.

Source: PHP password_needs_rehash (opens in a new tab) describes the Boolean result and verify-then-upgrade sequence.

5Read database helpers and timestamp arithmetic

The portal's q_one($sql, $parameters) returns one row as an associative array or null. q($sql, $parameters) executes a statement. The parameters array supplies values for ? placeholders, in order. These are course helpers, so their local headers define their contracts.

PHP
<?php
$row = ['n' => '4'];
$count = (int) $row['n'];
$limit = 5;
var_dump($count >= $limit);
$windowSeconds = 15 * 60;
echo $windowSeconds . "\n";
Output
bool(false)
900

(int) converts the database count to an integer. >= compares it with the threshold. 15 * 60 multiplies minutes by seconds. A SQL aggregate commonly names its output using COUNT(*) AS n; PHP then selects $row['n'].

time() returns the current Unix timestamp in seconds. time() - $windowSeconds computes the beginning of a recent window. date('Y-m-d H:i:s', $timestamp) formats a timestamp using the configured timezone. Store and compare timestamps under a consistent timezone because mixing local and UTC text can count the wrong rows.

PHP
<?php
$now = 1000;
$lastSeen = 100;
$idleLimit = 15 * 60;
var_dump($now - $lastSeen > $idleLimit);
var_dump(($now + 1) - $lastSeen > $idleLimit);
Output
bool(false)
bool(true)

At exactly 900 elapsed seconds, > is false; at 901 it becomes true. That small distinction explains an expiry boundary. It is not a recommendation to change the assignment's chosen policy.

Source: PHP time (opens in a new tab) defines the timestamp unit.

6Declare a local function and return from it

A function declaration introduces a name, parameters, and a body. A type annotation describes the expected value. : int declares the return type; : void declares that no value is returned.

PHP
<?php
function seconds_from_minutes(int $minutes): int
{
    return $minutes * 60;
}
echo seconds_from_minutes(15) . "\n";
Output
900

$minutes is the parameter inside the function. 15 is the argument at the call. return sends 900 back to the caller and ends that function call. A return inside an included script ends that script; exit stops execution of the request. Neither means “retry later.”

Question: What do functions such as sign_in_failed() or second_factor_failed() mean in lecture examples? They stand for application functions whose bodies must be supplied. PHP does not provide those names automatically. Do not copy an isolated fragment and assume all surrounding functions exist.

Source: PHP user-defined functions (opens in a new tab) explains declarations and parameters.

7Start a session and read its array

session_start() opens or resumes a session. It returns a Boolean indicating success. After a successful start, $_SESSION holds session data as an associative array. A cookie identifier selects server-side data; it does not contain the whole session array.

PHP
<?php
// Standalone array illustration, not a request that starts an actual session.
$session = ['account_id' => 42, 'last_seen' => 1000];
var_dump(isset($session['account_id']));
var_dump($session['account_id']);
unset($session['account_id']);
var_dump(isset($session['account_id']));
Output
bool(true)
int(42)
bool(false)

isset returns false for a missing or null entry. unset removes an entry. Assigning $_SESSION = [] empties the active session array; it does not itself delete the browser cookie or invalidate every other session belonging to the account.

Sources: PHP session_start (opens in a new tab) explains session opening and PHP isset (opens in a new tab) explains the existence test.

8Read cookie options and identifier regeneration

ini_set('session.use_strict_mode', '1') configures PHP to reject uninitialized session identifiers. session_set_cookie_params([...]) supplies cookie settings for the current script before session_start. Its array uses strings for keys and Boolean values for switches.

✓PHPSecure
<?php
// WHY: Configure the session cookie before it is issued so transport and script restrictions apply.
ini_set('session.use_strict_mode', '1');
session_set_cookie_params([
    'lifetime' => 0,
    'path' => '/',
    'secure' => true,
    'httponly' => true,
    'samesite' => 'Lax',
]);
if (!session_start()) {
    http_response_code(500);
    exit('Unable to start a session.');
}

Secure. Why: Configure the session cookie before it is issued so transport and script restrictions apply.

This is a web-request fragment; its output depends on the request and environment. On failure it stops with a generic message. On success it continues without printing text. Secure requires the appropriate HTTPS environment; the Orientation pages explain the course preview.

session_regenerate_id(true) asks PHP to issue a new identifier and delete the old associated session data. It returns false on failure. The Boolean argument true does not mean “the user is valid”; the password check establishes that separately. Set authenticated session values only after the identifier transition succeeds.

iA production session transition needs concurrency handling

PHP warns that immediately deleting old session data can cause races or lost sessions on unstable networks. The course demonstrates the true argument; production designs may use controlled invalidation timestamps. Keeping an old identifier must never let it retain authenticated access indefinitely.

Sources: PHP session_set_cookie_params (opens in a new tab) and PHP session_regenerate_id (opens in a new tab) document the options and return values.

9End access on both sides

session_destroy() destroys data associated with the current session. It does not automatically clear $_SESSION or remove the cookie. A sign-out routine therefore handles the array, the server record, and the browser cookie separately.

session_get_cookie_params() returns the cookie configuration as an array. session_name() returns the cookie name. setcookie can expire that cookie by using a timestamp in the past. In the lecture's positional call, the arguments after the value specify expiry, path, domain, Secure, and HttpOnly. Matching the original name, path, and domain matters because a different cookie does not replace the original one.

Question: Does setting $_SESSION = [] prove a previously captured identifier is invalid? No. Verify server-side invalidation by observing that the old identifier no longer grants access.

Question: Does browser closure prove sign-out? No. Browser session restoration can preserve session cookies, and another client can still replay its own copy. The server decides whether access remains valid.

Source: PHP session_destroy (opens in a new tab) documents what the function leaves unchanged.

10Generate random tokens and compare strings

random_bytes(32) returns 32 random bytes from a cryptographically secure generator. bin2hex converts those bytes to printable hexadecimal text, two characters per byte. The result therefore has 64 characters; hexadecimal conversion changes representation, not entropy.

✓PHPSecure
<?php
// WHY: Secure randomness makes a reset token unpredictable; printable encoding permits transport in a link.
$token = bin2hex(random_bytes(32));
echo strlen($token) . "\n";
echo strlen(hash('sha256', $token)) . "\n";
var_dump(hash_equals($token, $token));

Secure. Why: Secure randomness makes a reset token unpredictable; printable encoding permits transport in a link.

Output
64
64
bool(true)

The first 64 is the token's encoded length. The second 64 is the hexadecimal SHA-256 digest length. Equal lengths do not mean equal values or equal security properties. hash('sha256', $token) returns a digest string. It is appropriate for storing a full-entropy reset-token digest; a human password needs adaptive password hashing instead.

hash_equals($known, $supplied) compares strings using a timing-safe equality operation. Supply the trusted value first and the user-provided value second. Its Boolean result controls the branch. It does not validate a token's expiry, owner, or use history.

The portal's token_issue($username, $ttlSeconds) returns a token and stores its hash. token_check($token) returns the associated username or null. token_burn($token) marks it used. Separate check and burn calls are not automatically an atomic redemption operation; the security lecture explains that concurrency requirement.

Sources: PHP random_bytes (opens in a new tab), PHP bin2hex (opens in a new tab), and PHP hash_equals (opens in a new tab) explain these contracts.

11Read an MFA code check and a response

A TOTP code is text, even if it contains only digits. Converting 012345 to an integer loses the leading zero. preg_match('/\A[0-9]{6}\z/', $typed) asks whether the entire string is exactly six ASCII digits. It returns 1 for a match, 0 for no match, or false on an error.

PHP
<?php
$typed = '012345';
var_dump(is_string($typed));
var_dump(preg_match('/\A[0-9]{6}\z/', $typed) === 1);
var_dump((int) $typed);
Output
bool(true)
bool(true)
int(12345)

The pattern validates the format; it does not compute a TOTP or establish that the code belongs to the account. A vetted library computes the expected code and accepted time window. A complete verifier also limits attempts and prevents reuse.

In web handlers, http_response_code(401) selects a status. header('Retry-After: ' . $window) sends a header containing a joined string. header('Location: /login.php') sends a redirect header; it does not stop PHP. exit stops execution so protected statements after the redirect do not run. Send headers before output because PHP cannot reliably change headers after the response has begun.

✓Explain the branch you verified

In your report, identify the rejected condition and show the observed response because a status line alone does not establish which internal check caused it. Keep passwords and complete session identifiers out of evidence because they can grant access.

Sources: PHP preg_match (opens in a new tab) and PHP header (opens in a new tab) explain matching results and response headers.

12Check your understanding

What does pw_verify return? A Boolean, not an account row. The application separately looks up the account and checks whether the row exists.

What distinguishes password_needs_rehash from verification? It checks algorithm and settings. It does not establish that the supplied password matches.

What does $row['n'] select? The entry under the key n, such as the alias returned by a count query.

What does return do inside a helper? It ends that function and optionally sends a value back. It does not necessarily end the request.

What is changed by session_regenerate_id(true)? The current identifier changes and the old associated session data is deleted. Application authentication checks are still required.

What does session_destroy leave for the application to handle? The in-memory session array and browser cookie.

Why keep a six-digit code as a string? Leading zeros are meaningful, and string validation can enforce its exact length.

Does a 64-character hexadecimal token have 64 random bytes? No. A 32-byte token becomes 64 hexadecimal characters.

What should you do when an AI-produced fragment calls an undefined helper? Find its definition and contract before using it, because an illustrative name is not a PHP built-in and the fragment may depend on missing behavior.
