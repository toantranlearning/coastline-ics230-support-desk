A source excerpt contains an echo. A supplied response contains a tag. A report calls the issue confirmed. Those are three separate pieces of information. Reading the PHP helps you decide how they connect and what evidence is still missing.

This companion supports the M07 security-testing lecture. It uses small authored examples to practice source-to-sink tracing, type checks, alert records, and comparison of expected and observed results. These examples are not scan results. They do not run a scanner, make network requests, or replace evidence required by the assignment.

iKeep the evidence source visible

The module's teaching packet is simulated. Label its content as supplied simulated evidence, because a reviewer must be able to distinguish that material from behavior you personally observed in your authorized portal.

1Distinguish parsing a program from running it

PHP first needs syntactically valid code. A missing semicolon or unmatched brace can prevent successful parsing. Syntax checking can establish that the interpreter accepts the program's grammar. It cannot establish that the program's rule is correct or that a database, session, or file will be available at runtime.

PHP
<?php
$ownerId = 7;
$requesterId = 8;
echo "Requested record exists.\n";
Output
Requested record exists.

This valid program prints its message regardless of the two identifiers. Both variables are assigned, but neither is used in a permission decision. A syntax check cannot infer the missing ownership requirement.

★A successful language check has a limited conclusion

“This PHP parses” is different from “this operation enforces the intended rule.” Record the narrow conclusion because syntax acceptance does not demonstrate authorization, output safety, or environmental readiness.

The Orientation language and lab references explain how to check and run a file. This page concentrates on interpreting what those results establish.

2Follow assignments from a source to an output

A variable can carry the same untrusted value through several names. Assigning it to another variable does not validate or encode it.

✕PHPVulnerable
<?php
// WHY: Renaming input does not prevent its markup from reaching the HTML output.
$suppliedComment = '<b>Loan kit</b>';
$comment = $suppliedComment;
$displayValue = $comment;
echo '<div class="comment">' . $displayValue . "</div>\n";

Vulnerable. Why: Renaming input does not prevent its markup from reaching the HTML output.

Output
<div class="comment"><b>Loan kit</b></div>

This standalone example uses a local string to represent supplied data. In the lecture's web handler, $_POST['comment'] is the source. Here, $suppliedComment is the starting value. The assignments preserve it, the dot operators join it into HTML, and echo is the output sink.

The browser would interpret the bold element in this HTML text context. That establishes markup interpretation for this example. It is not evidence that a script ran, that another user saw it, or that a particular deployed route is reachable.

◆Taint tracking

Taint tracking follows values marked as untrusted through assignments and operations toward sensitive uses. A tool's model determines which sources, transformations, and sinks it recognizes. The trace identifies a path to investigate; the application's context determines the defensible finding.

Source: PHP assignment operators (opens in a new tab) explains assignment; OWASP Secure Code Review Cheat Sheet (opens in a new tab) describes reviewing inputs, flows, and dangerous uses.

3Identify a transformation and its context

The repair uses a type check before encoding the comment for its HTML text destination.

✓PHPSecure
<?php
// WHY: The string check protects the function call; encoding prevents accepted text from becoming HTML markup here.
$comment = '<b>Loan kit</b>';
if (!is_string($comment)) {
    exit("Invalid comment.\n");
}
$displayValue = htmlspecialchars($comment, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8');
echo '<div class="comment">' . $displayValue . "</div>\n";

Secure. Why: The string check protects the function call; encoding prevents accepted text from becoming HTML markup here.

Output
<div class="comment">&lt;b&gt;Loan kit&lt;/b&gt;</div>

is_string returns a Boolean. ! negates that result, so a nonstring enters the rejection branch. exit stops the script. htmlspecialchars returns a new string, which the assignment stores in $displayValue.

ENT_QUOTES includes both quote types, ENT_SUBSTITUTE replaces invalid encoding sequences, and | combines those flag bits. 'UTF-8' names the character encoding. The browser displays the literal <b>Loan kit</b> when this source appears in the HTML text node.

✕A recognized transformation is not a universal safety label

Review where the returned value is used because an HTML function does not establish safety for a SQL command, JavaScript expression, or shell argument. A static tool may recognize a function while lacking the context needed to judge that use.

Source: PHP htmlspecialchars (opens in a new tab) documents arguments and return behavior.

4Read a helper's body and return value

A helper can hide the transformation from the calling code. Its name is a clue, but its body establishes what it actually does.

PHP
<?php
function encode_html_text(string $value): string
{
    return htmlspecialchars($value, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8');
}
$value = 'Jordan & Lee';
$output = encode_html_text($value);
echo $output . "\n";
Output
Jordan &amp; Lee

The parameter declaration string $value describes the expected argument type. : string declares the return type. return gives the encoded value back to the caller. Calling the function does not automatically change a different variable; the assignment stores its returned result.

A comment such as // safe output is an annotation written by a person. It does not execute. A type declaration establishes a language-level type requirement, not permission or the correct output context. Review code and the actual contract together.

!Check whether the helper returns or writes

Inspect the helper before assuming its result reaches the intended sink because returning a string and directly echoing it produce different flows. A reviewer who confuses those behaviors may credit a control that the caller never uses.

Source: PHP return (opens in a new tab) explains returned values; PHP type declarations (opens in a new tab) describes type contracts.

5Represent an alert as a record

An associative array can hold the fields of an illustrative alert. Square brackets retrieve a field by key. This data structure is a practice representation, not a scanner's required export format.

PHP
<?php
$alert = [
    'id' => 'PRACTICE-01',
    'severity' => 'Low',
    'confidence' => 'Medium',
    'provenance' => 'Authored practice example',
];
echo $alert['id'] . "\n";
echo $alert['severity'] . ' / ' . $alert['confidence'] . "\n";
echo $alert['provenance'] . "\n";
Output
PRACTICE-01
Low / Medium
Authored practice example

Severity and confidence occupy different entries because they answer different questions. A string saying High does not prove that the weakness is deployed or that an incident occurred. Storing a label preserves the claim; it does not validate it.

$alert['missing'] ?? 'Not supplied' uses a default when a key is absent or null. That default describes a gap. It must not be replaced with an invented observation merely to fill the record.

Source: PHP arrays (opens in a new tab) describes key/value records and nested data.

6Use foreach to keep individual observations visible

A list of arrays can represent several observations. foreach takes one entry at a time and runs its block for that entry.

PHP
<?php
$observations = [
    ['route' => '/sample-a', 'status' => 'Needs context'],
    ['route' => '/sample-b', 'status' => 'Needs context'],
];
foreach ($observations as $observation) {
    echo $observation['route'] . ': ' . $observation['status'] . "\n";
}
Output
/sample-a: Needs context
/sample-b: Needs context

$observations contains the list. $observation receives the current entry on each iteration. Its route and status keys then identify that entry's fields. The loop does not automatically decide whether the two observations share one root cause.

iGrouping should preserve affected locations

You may group duplicate leads around a shared control while retaining the individual routes and evidence, because a repair and retest need to cover every relevant occurrence. A count of two entries is a count of entries, not necessarily two distinct vulnerabilities.

Source: PHP foreach (opens in a new tab) describes array iteration.

7Compare expected and observed results strictly

The next example records two authored practice cases. It does not send either request. The expected field is the planned result, while observed is a supplied example result.

PHP
<?php
$cases = [
    ['name' => 'Allowed case', 'expected' => 200, 'observed' => 200],
    ['name' => 'Denied case', 'expected' => 404, 'observed' => 200],
];
foreach ($cases as $case) {
    $matches = $case['observed'] === $case['expected'];
    echo $case['name'] . ': ' . ($matches ? 'matches' : 'differs') . "\n";
}
Output
Allowed case: matches
Denied case: differs

=== requires matching type and value. ? ... : ... is the ternary operator: it selects the first expression when the condition is true and the second when false. Here it selects a display word, not a permission decision.

A status comparison establishes only whether these integers match. A 200 response might contain a login page instead of the intended protected record. A refusal status could accompany an information leak in the body. The evidence must also identify the reached feature, identity, content, and state changes relevant to the claim.

▸The denied case needs investigation

The supplied status differs from the plan. That contradicts the expected status, but the status alone does not tell you what record was returned or why. Preserve the difference and obtain the missing context because a mismatch is a lead rather than a complete explanation.

Source: PHP comparison operators (opens in a new tab) documents strict comparisons and conditional expressions.

8Distinguish missing coverage from a failed control

A missing observation should remain missing. The following example displays a coverage gap explicitly instead of converting it into a passing test.

PHP
<?php
$case = ['name' => 'Second account comparison', 'observed' => null];
if ($case['observed'] === null) {
    echo "Result not supplied; ownership conclusion remains unestablished.\n";
} else {
    echo "An observation is available for review.\n";
}
Output
Result not supplied; ownership conclusion remains unestablished.

Null represents no value in this record. It does not mean the requester was refused. It does not mean the route was tested and passed. The condition preserves that difference so the report can state its limitation.

✓Describe the coverage you have

Separate attempted requests, reached features, established results, and gaps because counting an unobserved case as passed makes the conclusion broader than the evidence. The course assessment asks you to reason about those limits.

9Keep type failures separate from field rules

A type check prevents a string operation from receiving an array, but it does not establish that the string satisfies a length or permitted-value rule.

✓PHPSecure
<?php
// WHY: Checking the type first prevents the output encoder from receiving an array-shaped value.
$comment = ['Loan kit'];
if (!is_string($comment)) {
    echo "Rejected nonstring value.\n";
} else {
    echo htmlspecialchars($comment, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8') . "\n";
}

Secure. Why: Checking the type first prevents the output encoder from receiving an array-shaped value.

Output
Rejected nonstring value.

The rejection branch executes and the encoder is not called. In a web handler, a corresponding rejection commonly sets an HTTP status and terminates execution. These are separate operations: http_response_code(400) sets the status, and exit stops the script. A static review should trace whether later sensitive operations remain reachable after rejection.

Source: PHP is_string (opens in a new tab) defines the check; PHP http_response_code (opens in a new tab) defines status setting.

10Check your understanding

11Practice a mismatch and a coverage gap

Use section 7's two-case example. Change the denied case's supplied observation from integer 200 to integer 404. The expected output becomes Denied case: matches. Then change it to string '404'. The output becomes Denied case: differs because strict comparison sees a different type.
