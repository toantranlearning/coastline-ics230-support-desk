A training booking API receives {"location":"North"}. Its handler needs to read JSON, confirm which caller sent it, decide whether the caller may change the booking, and return a structured result. Each step uses different PHP operations. A successful JSON parse does not establish identity or permission.

The security lecture explains the API controls. This companion follows neutral booking and equipment examples through the PHP constructs used by the lecture and project. It does not supply a finished partner API.

★Keep parsing, authentication, and permission separate

Parsing establishes the structure of a value. Credential verification establishes a caller under the authentication design. Authorization decides the allowed action and object. Read the branches that connect these results before a database change occurs.

1Extract a route without treating it as permission

PHP
<?php
$path = '/api/bookings/41';
if (preg_match('#\A/api/([a-z][a-z0-9_-]*)(/.*)?\z#', $path, $matches) === 1) {
    echo $matches[1] . "\n";
    echo ($matches[2] ?? '') . "\n";
}
Output
bookings
/41

preg_match receives the pattern, input, and a variable for captured results. It returns 1 for a match, 0 for no match, or false for an error. Parentheses create captured groups. $matches[1] is the resource name; $matches[2] is the trailing path when present. ?? '' supplies the empty string if that group is absent.

\A and \z anchor the whole string. The # characters delimit this regular expression rather than becoming part of the accepted path. A router can construct a developer-controlled script path, check file_exists, place the remaining path in $_SERVER['PATH_INFO'], and require the script. __DIR__ names the directory containing the router source. require executes PHP in the included file; it is not a request to a remote URL.

An endpoint still validates PATH_INFO. For one booking, match an exact slash-and-digits shape, check numeric range, and convert the captured identifier deliberately. A routed identifier does not establish ownership.

Source: PHP preg_match (opens in a new tab) explains captures and return values.

2Read method, headers, and media type

$_SERVER['REQUEST_METHOD'] supplies request metadata such as GET or PATCH. A method decides which handler branch runs, not whether the caller is permitted. An unsupported method can receive 405 with an appropriate Allow header.

Headers commonly appear as HTTP_ entries: X-API-Key becomes HTTP_X_API_KEY, and Authorization becomes HTTP_AUTHORIZATION. Content-Type commonly appears as CONTENT_TYPE. Server configuration can affect availability, so use defaults and validate the resulting values.

PHP
<?php
$rawType = ' Application/JSON; charset=utf-8 ';
$pieces = explode(';', $rawType);
$type = strtolower(trim($pieces[0]));
echo $type . "\n";
var_dump($type === 'application/json');
Output
application/json
bool(true)

explode splits a string into an array at a delimiter. Index 0 selects the first component. trim removes outside whitespace. strtolower normalizes case. Those operations normalize the media-type comparison; they do not modify the body or validate its JSON.

Question: Does Content-Type: application/json guarantee a JSON body? No. The sender supplies the header. Parse the body and handle errors.

Source: PHP server variables (opens in a new tab) documents request metadata.

3Decode JSON and handle malformed input

✓PHPSecure
<?php
// WHY: An explicit parsing exception keeps malformed input from becoming an apparently absent value.
$raw = '{"location":"North","approved":false}';
try {
    $data = json_decode($raw, true, 8, JSON_THROW_ON_ERROR);
    echo $data['location'] . "\n";
    var_dump($data['approved']);
} catch (JsonException $error) {
    echo "Malformed JSON.\n";
}

Secure. Why: An explicit parsing exception keeps malformed input from becoming an apparently absent value.

Output
North
bool(false)

json_decode receives the raw string, an associative-result switch, maximum nesting depth, and flags. true converts JSON objects into associative arrays. 8 bounds nesting depth. JSON_THROW_ON_ERROR requests a JsonException when decoding fails. The catch branch runs for that failure; it does not run for valid JSON whose value is null.

A JSON body can be an object, list, number, string, Boolean, or null. is_array alone after associative decoding accepts both JSON objects and JSON lists. If an endpoint requires an object, preserve or validate that distinction explicitly rather than assuming every array represents the expected field map.

file_get_contents('php://input') reads the request body and returns a string or false. Check a read failure before calling strlen. strlen counts bytes, which is appropriate for a body-byte budget. Reading the entire body and only then checking its size limits later parsing work, but does not prevent the initial allocation; server limits or bounded streaming provide an earlier cap.

!Syntax validity is only the first check

Valid JSON can contain unknown fields, wrong types, excessive text, or unauthorized changes. Validate the expected structure and allowed fields before applying a write because decoding does not enforce that policy.

Source: PHP json_decode (opens in a new tab) defines its argument and error behavior.

4Identify fields that are not permitted

✓PHPSecure
<?php
// WHY: Reject unknown write fields so the client cannot silently set an ownership or privilege field.
$data = ['location' => 'North', 'owner_id' => 8];
$allowed = ['location', 'status'];
$unknown = array_diff(array_keys($data), $allowed);
echo json_encode(array_values($unknown), JSON_THROW_ON_ERROR) . "\n";

Secure. Why: Reject unknown write fields so the client cannot silently set an ownership or privilege field.

Output
["owner_id"]

array_keys returns the submitted keys. array_diff returns values in that list absent from the allowed list, preserving their original keys. array_values reindexes the result starting at zero, so JSON encoding produces a list rather than an object with an isolated numeric key.

$unknown !== [] uses strict comparison to ask whether the result is nonempty. For an allowed field, is_string checks its type; preg_match can check permitted characters and length; in_array($status, ['pending', 'approved'], true) checks a strict enumerated set.

$data['location'] ?? null treats a missing or null value alike. If the API must distinguish “do not change this field” from “set this field to null,” use an explicit presence check such as array_key_exists. The language default must match the API contract.

Source: PHP array_diff (opens in a new tab) explains preserved keys and comparison behavior.

5Read scope and ownership checks

A caller array might contain partner_id, scope, and expires. These keys are trusted only after the credential has been verified and its claims validated. require_scope($caller, $needed) is a course/application helper name, not a PHP built-in. Its body must enforce the comparison and stop on refusal.

PHP
<?php
$caller = ['partner_id' => 3, 'scope' => 'bookings:read'];
var_dump($caller['scope'] === 'bookings:read');
var_dump($caller['scope'] === 'bookings:write');
$parameters = [41, $caller['partner_id']];
echo implode(',', $parameters) . "\n";
Output
bool(true)
bool(false)
41,3

The scope check asks which action is permitted. A query using WHERE id = ? AND partner_id = ? uses the parameter array to connect an object identifier with that caller. The first placeholder receives 41; the second receives 3. Scope alone does not grant every booking.

The portal's q_one returns a row or null, q_all returns all matching rows, and q returns an executed PDO statement. Their local definitions prepare SQL and execute values separately. ->rowCount() returns an affected-row count for suitable statements; its interpretation depends on the driver and operation. A zero count can indicate no changed row, which is not universally proof that the object did not exist. Avoid turning driver-specific behavior into an authorization claim.

In SQL, COALESCE(?, location) chooses the parameter if it is non-null, otherwise the old column value. It cannot represent “set this column to null” through that pattern. Explain the omission/null behavior in the API design.

6Sign and verify the classroom token representation

The course hmac_sign($value) returns value.signature. hmac_verify($signed) returns the verified value or null. Their definitions in lib/hmac.php use a signing key from the environment, HMAC-SHA-256, and hash_equals. The helper proves integrity under that shared key; it does not encrypt the payload or enforce expiry.

This standalone illustration uses a visibly artificial demonstration key and a different booking scope. It demonstrates the operations, rather than producing a deployed credential.

✓PHPSecure
<?php
// WHY: Compare the computed keyed tag before treating the payload as authenticated claims.
$demoKey = 'classroom-only-demonstration-key';
$payload = '3|bookings:read|2000';
$tag = hash_hmac('sha256', $payload, $demoKey);
$signed = $payload . '.' . $tag;
$dot = strrpos($signed, '.');
$receivedPayload = substr($signed, 0, $dot);
$receivedTag = substr($signed, $dot + 1);
var_dump(hash_equals(hash_hmac('sha256', $receivedPayload, $demoKey), $receivedTag));
var_dump(hash_equals(hash_hmac('sha256', '8|bookings:read|2000', $demoKey), $receivedTag));

Secure. Why: Compare the computed keyed tag before treating the payload as authenticated claims.

Output
bool(true)
bool(false)

hash_hmac takes algorithm, message, and secret key, returning a hexadecimal tag by default. strrpos locates the last dot, returning an integer position or false. Check that failure before using it. substr($signed, 0, $dot) selects the preceding payload; substr($signed, $dot + 1) selects the following tag. hash_equals receives the trusted computed tag first and supplied tag second.

The altered partner identifier produces a different tag. A valid tag still does not establish that each field has the expected type, range, scope, audience, or useful lifetime. Verify integrity first, then validate and use claims.

Source: PHP hash_hmac (opens in a new tab) defines keyed hashing.

7Parse a verified payload deliberately

✓PHPSecure
<?php
// WHY: Exact field shape and typed claims prevent malformed signed text from being interpreted as a different credential.
$verifiedPayload = '3|bookings:read|2000';
$parts = explode('|', $verifiedPayload);
if (count($parts) !== 3) {
    exit('Invalid token shape');
}
[$partnerText, $scope, $expiryText] = $parts;
$partner = filter_var($partnerText, FILTER_VALIDATE_INT, ['options' => ['min_range' => 1]]);
$expiry = filter_var($expiryText, FILTER_VALIDATE_INT, ['options' => ['min_range' => 1]]);
if ($partner === false || $expiry === false || $scope !== 'bookings:read') {
    exit('Invalid token claims');
}
$now = 1999;
var_dump($now >= $expiry);
var_dump(2000 >= $expiry);

Secure. Why: Exact field shape and typed claims prevent malformed signed text from being interpreted as a different credential.

Output
bool(false)
bool(true)

Bracket assignment destructures the array into three variables. count checks the number of pieces. filter_var returns a validated integer or false. >= means the token is expired when current time reaches its expiry, including equality. In a handler, time() supplies the current timestamp.

str_starts_with($authorization, 'Bearer ') checks the prefix. substr($authorization, 7) removes its seven characters. Those string operations extract a credential; they do not authenticate it. A production parser also handles the documented authentication syntax and rejects malformed or empty credentials.

iA signed token is not a full OAuth implementation

The classroom representation demonstrates integrity, scope, and expiry. It does not implement user consent, standardized OAuth flows, refresh-token controls, or every production token validation requirement. Explain that distinction in the design document because a shared signing key alone does not establish delegated user permission.

8Clamp pagination and read a recent counter

✓PHPSecure
<?php
// WHY: A numeric ceiling keeps one list request from asking the database for an unbounded result.
$requested = 500;
$limit = max(1, min($requested, 50));
$offset = max(0, -2);
echo $limit . "\n";
echo $offset . "\n";
$now = 1000;
$windowStart = $now - 60;
echo $windowStart . "\n";

Secure. Why: A numeric ceiling keeps one list request from asking the database for an unbounded result.

Output
50
0
940

min chooses the smaller argument; max chooses the larger. This clamps a number already established as an integer. Casting an arbitrary submitted array or malformed text with (int) is not a substitute for validating the input's type and numeric meaning.

A recent counter query uses a timestamp bound such as made_at > ?. Casting the returned count with (int) normalizes the aggregate before comparing it to a threshold. header('Retry-After: 60') communicates a retry delay, and 429 communicates rate limiting. A separate count and insert sequence can race under simultaneous requests; production enforcement needs atomic coordination. Large offsets can still require expensive database work even with a small result limit.

Question: Does clamping a list limit authorize its rows? No. Keep the caller's ownership predicate in the same query.

9Return a JSON response and stop the handler

http_response_code($status) selects a status. header('Content-Type: application/json') declares the body type. json_encode($body, JSON_THROW_ON_ERROR) returns serialized text. echo writes it, and exit ends execution. Headers must be set before output.

A helper declaration function respond(int $status, array $body): never means it never returns normally to its caller. It must exit or throw on every path. never is a PHP return type introduced in PHP 8.1; it does not mean the function cannot fail.

try and catch (Throwable $error) can cover a failed helper call. Throwable includes errors and exceptions. A generic client response can include a reference generated with bin2hex(random_bytes(4)); four bytes produce eight hex characters. The corresponding server log can record appropriate diagnostics, with credentials and private payloads omitted. The reference links two records without exposing the raw exception message.

Source: PHP never return type (opens in a new tab) defines nonreturning functions.

10Read CORS branches and outbound-request options

An Origin header arrives as requester data. A CORS handler can compare it with a permitted origin and emit Access-Control-Allow-Origin for that exact origin. An OPTIONS preflight can receive 204 with permitted methods and headers. The browser applies CORS; a command-line client does not need that browser permission. Every route therefore still authenticates and authorizes the actual request.

parse_url($url) returns components such as scheme and host, or false on failure. strtolower normalizes host case; strict in_array tests the entire host against a developer-written list. Host-prefix matching is insufficient: a longer attacker-controlled hostname can begin with an allowed name.

The PHP cURL extension is distinct from the command-line curl program. curl_init($url) creates a handle. curl_setopt_array($handle, $options) supplies an array of option constants and values. For example, CURLOPT_FOLLOWLOCATION => false disables redirects, CURLOPT_TIMEOUT => 5 bounds the operation, and CURLOPT_RETURNTRANSFER => true asks curl_exec to return the body instead of printing it.

curl_exec($handle) returns a result or false. Check errors and response status separately; an HTTP error response can still produce a body. A timeout is not a response-size cap. Redirect policy, permitted resolved addresses, connection behavior, and maximum response bytes remain separate controls. The lecture explains the network policy needed to address DNS changes and private destinations.

Source: PHP curl_setopt_array (opens in a new tab) documents bulk option configuration.

Can JSON null and a parse failure look alike without exception mode? Yes. JSON_THROW_ON_ERROR makes malformed input a distinct failure path.

Does hmac_verify check expiry? No. Its local contract returns intact payload text or null; the handler checks expiry and other claims afterward.

Does an accepted scope establish object ownership? No. Scope authorizes a class of action; the ownership query connects it to permitted objects.
