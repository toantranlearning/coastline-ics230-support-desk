PHP writes the response; the browser interprets it. This companion helps you read PHP templates, array entries, loops, encoding calls, and the JavaScript that receives their output. The main lecture explains cross-site scripting and the controls. The examples here use equipment labels and reviews rather than providing the call-notes assignment repair.

★There are two programs to follow

PHP executes on the server and produces text. HTML and JavaScript in that response are interpreted by the browser. A PHP expression can finish correctly while producing text that the browser interprets incorrectly.

1Read the arguments to htmlspecialchars

A function call supplies arguments inside parentheses. This complete example runs as a standalone PHP program.

✓PHPSecure
<?php
// WHY: HTML encoding represents the supplied brackets and quotes as text for this HTML destination.
$label = '<b>Loan kit</b> & "spare"';
$encoded = htmlspecialchars($label, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8');
echo $encoded . "\n";

Secure. Why: HTML encoding represents the supplied brackets and quotes as text for this HTML destination.

Output
&lt;b&gt;Loan kit&lt;/b&gt; &amp; &quot;spare&quot;
1. Read the arguments to htmlspecialchars. Columns: Argument, Meaning.
ArgumentMeaning
$labelThe string to represent as HTML text
ENT_QUOTESEncodes both kinds of quote as well as HTML-sensitive characters
ENT_SUBSTITUTEReplaces invalid character sequences instead of failing with an empty result
`ENT_QUOTES \ENT_SUBSTITUTE`Combines the two flag options using bitwise OR
'UTF-8'Names the character encoding used to interpret the input string

The function returns a new string. It does not automatically change $label; assigning its result to $encoded stores that result. The period in $encoded . "\n" concatenates the encoded string with a newline.

In an HTML text node, the browser displays <b>Loan kit</b> & "spare" as characters. No bold element is created from that encoded text. The displayed value and HTML source are different representations of the same label.

Source: PHP htmlspecialchars (opens in a new tab) explains the arguments, flags, and returned string.

2Read mixed PHP and HTML

<?php enters PHP mode and ?> leaves it. Text outside PHP mode is written to the response. <?= expression ?> is a short echo expression: it writes the expression's value at that position.

✓PHPSecure
<?php
// WHY: Encoding each output expression preserves the label in both HTML text and the quoted attribute.
$label = 'Jordan & Lee';
?>
<p><?= htmlspecialchars($label, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8') ?></p>
<input value="<?= htmlspecialchars($label, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8') ?>">

Secure. Why: Encoding each output expression preserves the label in both HTML text and the quoted attribute.

Output
<p>Jordan &amp; Lee</p>
<input value="Jordan &amp; Lee">

The first expression writes into paragraph text. The second writes inside the quoted value attribute. Quotes around the HTML attribute are part of HTML. Quotes around 'UTF-8' are part of the PHP argument.

Short echo syntax does not encode automatically. The function call performs that operation. Encoding the paragraph occurrence does not protect the input occurrence, because these are separate output expressions.

!Recognize the whole destination

Check the surrounding HTML before selecting an encoder, because ordinary text, quoted attributes, URLs, event handlers, and script blocks have different interpretation rules. HTML encoding alone does not validate a link's scheme or safely construct JavaScript code.

Source: PHP escaping from HTML (opens in a new tab) describes mixed templates.

3Read a loop over stored records

Database results commonly arrive as arrays of rows. A row is an associative array whose keys name fields. This standalone example creates those rows locally so you can follow the loop without a database.

✓PHPSecure
<?php
// WHY: Encoding inside the loop protects every displayed row's value.
$reviews = [
    ['body' => 'Ready & inspected'],
    ['body' => '<b>Loan kit</b>'],
];
foreach ($reviews as $review) {
    echo '<p>'
        . htmlspecialchars($review['body'], ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8')
        . "</p>\n";
}

Secure. Why: Encoding inside the loop protects every displayed row's value.

Output
<p>Ready &amp; inspected</p>
<p>&lt;b&gt;Loan kit&lt;/b&gt;</p>

foreach ($reviews as $review) assigns the next row to $review and executes the block once for that row. $review['body'] selects the current row's body. After the first iteration, the same statements run for the second row.

A string read from storage remains a string originally supplied by someone. The array access does not establish that the browser may interpret it as HTML.

Source: PHP foreach (opens in a new tab) explains iteration over arrays.

4Distinguish defaults, checks, and function returns

The lecture uses $_GET['next'] ?? '/'. $_GET is an array of parsed query parameters. ?? supplies the fallback when the entry is missing or null; it does not validate a present value. A request can supply an array rather than the string a function expects.

✓PHPSecure
<?php
// WHY: Checking the type before calling string functions handles array-shaped request values deliberately.
$raw = $_GET['label'] ?? '';
if (!is_string($raw)) {
    http_response_code(400);
    exit('Invalid request.');
}
$label = trim($raw);

Secure. Why: Checking the type before calling string functions handles array-shaped request values deliberately.

This web-handler fragment needs an HTTP request. For ?label=Loan, $raw is a string and execution reaches trim. For ?label[]=Loan, it is an array and the handler rejects it. http_response_code sets the status; exit stops execution. The fragment checks type only; the field still needs its business rules.

The lecture's URL helper also uses parse_url, isset, and return. parse_url extracts URL components; its result can be an array or false. isset($parts['scheme']) checks whether a non-null scheme entry exists. return '/' returns a chosen fallback from a function; it does not terminate the caller's script.

The helper's acceptance rule is a URL policy, separate from HTML representation. A URL parser extracts components but does not establish that a destination is authorized.

Source: PHP parse_url (opens in a new tab) documents the parser's result and limitations.

5Pass data to JavaScript without making it code

A quoted data- attribute can hold a value for a separately defined click handler. This web-page fragment demonstrates that separation.

✓PHPSecure
<?php
// WHY: The identifier is data in a quoted attribute; the handler later writes it as text.
$equipmentId = 'kit-7';
?>
<button id="open-kit" data-equipment="<?= htmlspecialchars($equipmentId, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8') ?>">Open</button>
<p id="selection"></p>
<script src="../modules/module-06//assets/equipment-selection.js" defer></script>

Secure. Why: The identifier is data in a quoted attribute; the handler later writes it as text.

The referenced JavaScript file would contain the following code. It is browser JavaScript, not PHP.

✓JavaScriptSecure
// WHY: textContent displays the identifier without interpreting it as HTML.
const button = document.getElementById('open-kit');
const selection = document.getElementById('selection');
button.addEventListener('click', () => {
    selection.textContent = button.dataset.equipment;
});

Secure. Why: textContent displays the identifier without interpreting it as HTML.

After the click, the paragraph displays kit-7. document.getElementById finds an element. addEventListener registers a function to run on a click. dataset.equipment reads the data-equipment attribute as a string. textContent supplies text rather than HTML markup.

An attribute named onclick contains executable JavaScript, whereas data-equipment contains data. Moving a value into a data attribute does not protect every future use: the JavaScript must still choose an appropriate operation when it displays or uses that value.

location.hash is the browser's URL fragment. The fragment is not sent in the HTTP request, so PHP cannot validate the fragment value it never receives. Client code that copies fragment data into innerHTML creates an additional browser interpretation boundary.

Source: MDN textContent (opens in a new tab) explains text insertion; MDN dataset (opens in a new tab) describes data attributes.

6Serialize structured data as JSON

json_encode turns a PHP value into JSON text. Named array entries become JSON object properties.

✓PHPSecure
<?php
// WHY: JSON serialization represents string data without constructing executable JavaScript statements.
$payload = ['label' => '<b>Loan kit</b>'];
echo json_encode(
    $payload,
    JSON_HEX_TAG | JSON_HEX_AMP | JSON_HEX_APOS | JSON_HEX_QUOT | JSON_THROW_ON_ERROR
) . "\n";

Secure. Why: JSON serialization represents string data without constructing executable JavaScript statements.

Output
{"label":"\u003Cb\u003ELoan kit\u003C\/b\u003E"}

\u003C represents < and \u003E represents >. A JSON parser reconstructs the original label. The JSON_HEX_* flags represent HTML-sensitive characters with escapes, useful when JSON data is embedded in an HTML script-data element. JSON_THROW_ON_ERROR makes serialization failure raise an exception; a production handler needs a controlled error path.

JSON representation protects neither a later innerHTML assignment nor an arbitrary event-handler construction. Follow the parsed value to its eventual browser operation.

Source: PHP json_encode (opens in a new tab) describes serialization flags and failure behavior.

7Read the policy-header construction

The lecture constructs a nonce with base64_encode(random_bytes(16)). A nonce is a fresh unpredictable value shared between the response's Content Security Policy and its permitted script element.

random_bytes(16) returns 16 random bytes. base64_encode turns those bytes into a printable representation. The generated value varies per response, so there is no fixed expected nonce string. A double-quoted PHP string can interpolate $nonce; periods concatenate separate header-string parts.

The policy is sent with header before response output. The matching script attribute is written into the HTML. A nonce-based policy supplements appropriate output handling; it does not turn a dangerous output expression into a safe one.

Regular-expression removal is a different operation. preg_replace replaces pattern matches; it does not implement the browser's HTML parser. Adding another tag name to a removal expression does not supply a complete HTML sanitizer.

Source: PHP random_bytes (opens in a new tab) documents random byte generation; PHP preg_replace (opens in a new tab) documents pattern replacement.
