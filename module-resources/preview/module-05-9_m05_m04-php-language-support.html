An inventory page lets a staff member look up an equipment label. A label such as Builder's kit contains punctuation that belongs to the label. The PHP code must send that label as a database value while keeping the SQL instruction separate. This companion explains the statements that make that separation happen.

The security lecture explains injection and the controls for databases, operating-system commands, and file paths. Here you will follow function arguments, return values, arrays, and branches. These equipment examples do not provide the sign-in or customer-search assignment repair.

★Identify what the call receives

$pdo->prepare($sql) receives a SQL template. $statement->execute($values) receives the values. A prepare call cannot protect a request value already joined into the template.

1Read variables, strings, and object methods

$ begins a variable name. = assigns a value. Quotes delimit a string; they are not normally part of its value. . joins strings, and ; ends a statement.

PHP
<?php
$label = "Builder's kit";
$pattern = '%' . $label . '%';
echo $label . "\n";
echo $pattern . "\n";
Output
Builder's kit
%Builder's kit%

Double quotes allow the apostrophe inside this string without ending it. The two percent signs are added to the pattern, not the original label. In SQL LIKE, they will mean “any sequence of characters.” They are not PHP operators inside the string.

$pdo->prepare(...) calls a method on an object. -> means “use this object's method or property.” PDO::FETCH_ASSOC names a class constant; :: does not call a method on your connection object. new PDO(...) constructs a connection object.

Question: Does changing PHP quote style make a concatenated SQL query safe? No. PHP string syntax determines how PHP builds the string. The database later interprets the resulting SQL under its own grammar.

Source: PHP strings (opens in a new tab) explains quotes, interpolation, and string contents.

2Create a small database and prepare a statement

This standalone example creates a temporary in-memory SQLite database. It disappears when this PHP process ends and does not change your course portal.

✓PHPSecure
<?php
// WHY: Separate the SQL template from the label so punctuation remains part of a bound value.
$pdo = new PDO('sqlite::memory:');
$pdo->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);
$pdo->setAttribute(PDO::ATTR_DEFAULT_FETCH_MODE, PDO::FETCH_ASSOC);
$pdo->exec('CREATE TABLE equipment (id INTEGER PRIMARY KEY, label TEXT)');
$insert = $pdo->prepare('INSERT INTO equipment (id, label) VALUES (?, ?)');
$insert->execute([1, "Builder's kit"]);
$insert->execute([2, 'Loan camera']);
$statement = $pdo->prepare('SELECT id, label FROM equipment WHERE label = ?');
$statement->execute(["Builder's kit"]);
$row = $statement->fetch();
echo $row['id'] . ' | ' . $row['label'] . "\n";

Secure. Why: Separate the SQL template from the label so punctuation remains part of a bound value.

Output
1 | Builder's kit

Read the sequence carefully:

  1. new PDO('sqlite::memory:') returns the connection object. The string is its data source name, or DSN.
  2. setAttribute configures the connection. Exception mode makes database failures throw a PDOException. Associative fetch mode names row entries by column name.
  3. exec executes fixed SQL and returns an affected-row count. The table definition above is developer-written SQL containing no requester values.
  4. prepare returns a PDOStatement on success. With exception mode, failure throws rather than providing a usable statement.
  5. execute([1, "Builder's kit"]) supplies the values in an indexed array. The first value corresponds to the first ?; the second to the second ?. execute returns a Boolean indicating success.
  6. fetch retrieves the next result row. Here it returns an associative array with id and label keys. After the results are exhausted, it returns false.
  7. Bracket expressions select those keys, and echo writes the selected values.

◆Connection and statement are different objects

The connection opens access to a database. The statement represents one prepared operation and its results. Calling fetch on a connection is not the same as fetching from a statement.

Source: PHP PDO::prepare (opens in a new tab) documents statement creation and placeholder limits.

3Match placeholders to array values

A positional placeholder is ?; its value comes from array order. A named placeholder is :label; its value comes from the corresponding array key. Use one style consistently in a statement.

✓PHPSecure
<?php
// WHY: A named marker receives a value separately instead of inserting that value into SQL text.
$pdo = new PDO('sqlite::memory:');
$statement = $pdo->prepare('SELECT :label AS label, :quantity AS quantity');
$statement->execute(['label' => 'Loan camera', 'quantity' => 2]);
$row = $statement->fetch(PDO::FETCH_ASSOC);
echo $row['label'] . ' | ' . $row['quantity'] . "\n";

Secure. Why: A named marker receives a value separately instead of inserting that value into SQL text.

Output
Loan camera | 2

=> associates an array key with a value. The names in the SQL and array correspond. In positional code such as execute(['open', 'yusuf']), the values correspond to the first and second markers. Reversing them changes what the query asks.

Do not put quotes around a marker. In WHERE label = '?', the question mark is part of a SQL string literal, not a placeholder. Likewise, one marker supplies one complete value; it does not stand for an entire comma-separated list or a column name.

Question: Does execute return the matching rows? No. It executes the statement. Fetch the rows afterward.

Source: PHP PDOStatement::execute (opens in a new tab) describes positional and named parameter arrays.

4Read one row, all rows, and no rows

PHP
<?php
$pdo = new PDO('sqlite::memory:');
$statement = $pdo->query("SELECT 'Camera' AS label UNION ALL SELECT 'Tripod'");
$rows = $statement->fetchAll(PDO::FETCH_ASSOC);
echo count($rows) . "\n";
foreach ($rows as $row) {
    echo $row['label'] . "\n";
}
$empty = $pdo->query('SELECT 1 AS id WHERE 0 = 1');
var_dump($empty->fetch(PDO::FETCH_ASSOC));
var_dump($empty->fetchAll(PDO::FETCH_ASSOC));
Output
2
Camera
Tripod
bool(false)
array(0) {
}

query executes SQL directly and returns a statement. The example uses fixed developer-written SQL. Passing an untrusted concatenated string to query is a different security decision.

fetchAll returns an array of rows, possibly empty. foreach ($rows as $row) runs its body once for each row and assigns that row to $row. count returns the number of array entries. var_dump displays both a value and its type, making false distinguishable from an empty array.

!No result is a normal outcome

Test whether a row exists before selecting its keys because fetch can return false. An absent row must not become a successful authentication or authorization decision through an unchecked assumption.

Source: PHP PDOStatement::fetch (opens in a new tab) documents row retrieval and false on exhaustion.

5Read the course query helper contracts

The portal's lib/query.php wraps PDO. These are local functions whose definitions depend on db(), the function returning the portal's configured connection.

5. Read the course query helper contracts. Columns: Call, Arguments, Return value.
CallArgumentsReturn value
q($sql, $params)SQL template and ordered values arrayExecuted PDOStatement
q_one($sql, $params)Same two argumentsFirst associative row, or null
q_all($sql, $params)Same two argumentsArray containing all rows, possibly empty

q prepares the SQL and then executes the parameter array. q_one calls fetch and converts its false result to null. Its declaration : ?array means “array or null.” q_all calls fetchAll; : array means its return value is an array.

The optional parameter declaration array $params = [] supplies an empty array when the caller omits the second argument. It does not make concatenated requester SQL safe. The helper's precondition requires placeholders for request-derived values.

PHP
<?php
$row = null;
$result = $row === null ? 'No matching equipment' : $row['label'];
echo $result . "\n";
Output
No matching equipment

=== compares type and value. The ternary expression condition ? first : second selects its first expression when the condition is true and its second otherwise. Only the selected expression is evaluated here, so the null row's key is not accessed.

require_once __DIR__ . '/lib/query.php'; loads the helper definitions once. __DIR__ is the current file's directory. return inside a helper sends its result back and ends the function call. The lecture's show(...) is an example output helper, not a PHP built-in; its definition must be present before calling it.

✕A helper cannot undo unsafe SQL construction

Joining a requester value into $sql before calling q has already placed that value in the instruction. The helper prepares the string it receives; it cannot infer which pieces should have been parameters.

6Bind a LIKE pattern as one value

✓PHPSecure
<?php
// WHY: The complete LIKE pattern is bound as data; its percent signs stay outside the SQL template.
$pdo = new PDO('sqlite::memory:');
$statement = $pdo->prepare('SELECT :label LIKE :pattern AS matched');
$term = 'camera';
$pattern = '%' . $term . '%';
$statement->execute(['label' => 'Loan camera', 'pattern' => $pattern]);
echo $statement->fetchColumn() . "\n";

Secure. Why: The complete LIKE pattern is bound as data; its percent signs stay outside the SQL template.

Output
1

fetchColumn returns a value from one column of the next row, rather than an associative row. The default selects the first column. Here SQLite returns 1 for the true comparison.

Binding prevents the pattern from rewriting SQL grammar. It does not remove the special search meaning of % or _ inside the supplied pattern. If the feature promises literal substring matching, its design must separately escape those pattern characters using a documented SQL escape character.

Question: Where do the wildcard percent signs belong? In the bound pattern value. The template uses a bare placeholder for that entire pattern.

7Map a sort key and validate a numeric limit

✓PHPSecure
<?php
// WHY: A requester selects an allowed key; only developer-written column names can reach SQL grammar.
$columns = ['label' => 'label', 'added' => 'id'];
$requested = 'added';
if (!is_string($requested) || !isset($columns[$requested])) {
    exit('Invalid sort choice');
}
$column = $columns[$requested];
echo $column . "\n";
$limit = filter_var('2', FILTER_VALIDATE_INT, [
    'options' => ['min_range' => 1, 'max_range' => 50],
]);
var_dump($limit);

Secure. Why: A requester selects an allowed key; only developer-written column names can reach SQL grammar.

Output
id
int(2)

isset tests whether the map contains a non-null value for the key. ! means NOT. || means OR and short-circuits, so a wrong-type request does not proceed to key selection. The request chooses added, but the map supplies id.

filter_var receives a value, a filter constant, and an options array. FILTER_VALIDATE_INT returns the validated integer, or false when validation fails. Test with === false because zero is an integer value and may be valid in other policies.

bindValue(1, $limit, PDO::PARAM_INT) binds the value to positional marker 1 explicitly as an integer. Positions start at 1, while ordinary PHP indexed arrays start at 0. bindParam instead binds a variable by reference; the value can change before execution. The assignment uses the course helpers, so understand these direct PDO calls without replacing helper contracts arbitrarily.

Source: PHP PDOStatement::bindValue (opens in a new tab) explains marker positions and type arguments.

8Read exception handling and safe responses

PHP
<?php
$pdo = new PDO('sqlite::memory:');
$pdo->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);
try {
    $pdo->query('SELECT label FROM missing_equipment');
    echo "Query completed.\n";
} catch (PDOException $error) {
    echo "Equipment lookup unavailable.\n";
}
Output
Equipment lookup unavailable.

try contains operations that may throw. catch receives a matching exception object. $error->getMessage() obtains its message; a web application can log appropriate diagnostic detail with error_log, while showing a generic response to the requester. Avoid logging secrets or complete credentials because logs can expose them to additional readers.

http_response_code(500) selects an HTTP status; header(...) sets a response header; exit(...) writes its optional message and ends execution. A redirect header alone does not prevent later statements from running.

For MySQL, a connection options array can set PDO::ATTR_EMULATE_PREPARES => false. This is driver-specific configuration, not a PHP string-escaping function. The course portal uses SQLite; it does not need a MySQL DSN or MySQL emulation setting.

Source: PHP PDO error handling (opens in a new tab) explains exception mode.

9Understand command calls without running a shell

shell_exec($command) gives a command string to a shell and returns its output or a failure-related result. exec, system, and passthru have different output contracts, but all require careful attention to the interpreter receiving the command. The lecture explains why avoiding the shell is often the stronger design.

proc_open(['echo', 'Hello', $name], [1 => ['pipe', 'w']], $pipes) uses an argument array to launch a process directly. Its first array names the program and its individual arguments. The descriptor array describes output descriptor 1 as a pipe; the created stream appears in $pipes[1]. stream_get_contents reads that stream, fclose closes it, and proc_close waits for the process and returns its exit status. Check whether process creation succeeded before using the pipes.

This array form prevents a semicolon inside one argument from becoming shell command syntax. It does not prove that the program or its options are permitted. A value beginning with a dash can still have meaning to the called program.

escapeshellarg quotes one shell argument under the platform's rules. It does not validate business meaning or protect a separately concatenated program name. These are language explanations; follow ROE and course environment restrictions rather than treating command examples as permission to run security tools.

Source: PHP proc_open (opens in a new tab) documents argument arrays and stream descriptors.

10Read file paths and loader calls

include and require load a PHP file and execute its PHP code. require failure stops normal execution with an error. file_get_contents instead reads bytes and returns a string or false. A requested filename therefore needs a different control from an SQL value.

✓PHPSecure
<?php
// WHY: The map supplies the path, keeping a request from naming an arbitrary file to execute.
$pages = ['guide' => '/training/pages/guide.php', 'help' => '/training/pages/help.php'];
$key = 'help';
if (!is_string($key) || !isset($pages[$key])) {
    exit('Unknown page');
}
echo $pages[$key] . "\n";

Secure. Why: The map supplies the path, keeping a request from naming an arbitrary file to execute.

Output
/training/pages/help.php

The example prints the selected path; it does not load a file. realpath($path) resolves an existing path and returns its canonical absolute form, or false on failure. Check that both the base and candidate resolve before checking containment.

str_starts_with($candidate, $base . '/') asks whether the candidate begins with the base directory plus a separator. The separator matters: /training/docs-extra begins with /training/docs but is a different directory. Resolution and a prefix check also do not eliminate races if an attacker can change filesystem entries between checking and use.

Source: PHP realpath (opens in a new tab) documents canonicalization and false on failure.

Does prepare by itself bind a value? No. Supply the values through execute or binding calls, and keep them out of the template.

Why can a label be bound but a sort column cannot? A label is data. A column name is SQL structure; choose it from a developer-written map.

Does a value read from the database become trusted automatically? No. A previously stored hostile value can reach another unsafe concatenated query, producing second-order injection.

Does hiding database errors stop blind injection? No. Response differences can reveal information even when no exception text is visible. Correct value binding is still required.

What makes your evidence useful? Record the actual before-and-after behavior and legitimate-use checks. Predicted output from an AI or this example fixture is not an observation of your repaired portal.
