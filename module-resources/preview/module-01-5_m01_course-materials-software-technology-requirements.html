Read this page during week one, before your first lab. Everything here is free, and everything runs in a web browser.

No textbook required: total cost $0

There is nothing to buy and no access code to enter. Your lectures are the module pages; the source material behind them is CLARK, your reference material from OWASP and the PHP Manual, and your lab target is the TechCorp customer portal, which runs as your own course environment. You sign in to it from a browser in Module 01 and repair it for the rest of the term. Module 01 walks you through Google sign-in and lab setup. Download the supplied Word report from Canvas and edit it in Word or Word Online.

Optional, not required: Tanya Janca, Alice and Bob Learn Secure Coding (Wiley, 2025). A good book if you want a second voice on the same material. Check the Coastline Online Library (opens in a new tab) (opens in a new tab) before buying anything.

Software and tools

There is nothing to install. Everything you need runs in a web browser, so a Chromebook or a school computer is enough. You download finished reports, changed source files, and evidence for submission; you do not need administrator rights, and you do not set up a code-hosting account of any kind.

Your work happens in your own course environment, which runs in Google Cloud Shell. The instance has an editor, so you read and change the portal's code right in the browser. Module 01 walks you through signing in and opening the editor for the first time. The workspace contains original source in site/ (port 8080), working repairs in fixed/ (port 8081), and reports/ outside both portals. When an incident arrives, reproduce it on site, edit the code in fixed, and test the working portal. Submit changed source files with your report. The Working in Google Cloud Shell page is your standing reference for that environment: getting back in, resetting, and fixing problems.

Use a modern web browser (Chrome, Edge, Firefox, or Safari), kept up to date, and access to Word or Word Online for the report. You must be able to download and upload files. Cloud Shell Editor does not edit Word documents.

Work locally if you prefer (optional, unsupported)

If you would rather use a desktop editor, you can work on a copy of the portal on your own machine instead. This path is optional and not supported: you install PHP 8.2 or newer and an editor such as VS Code, and you handle any setup problems yourself. The course environment is the path for code and tests; reports are completed separately in Word or Word Online. If you are not sure, use the course environment.

Word reports and downloads

The Canvas assignment provides the .docx report. Its corporate narrative, policies, and management record are supplied case context. Read them, then complete only the marked [STUDENT] entries. Keep every EXAMPLE as a model, add your answers below it, paste screenshots into the document, and update Revision History. Word report templates are not stored in the student code repository.

Save a copy on your computer or in your document storage, check that it still ends in .docx, and upload it to Canvas with the required changed code and assignment.md. See Word Reports and Assignment Files.

Lab safety and authorized use

This is the most important rule in the course.

Security testing is powerful, and using it against a system you do not own or have written permission to test is a violation of the Coastline student conduct code and, under California Penal Code section 502 and the federal Computer Fraud and Abuse Act, a crime. Curiosity, good intentions, and "I did not change anything" are not defenses.

You may test: your own copy of the TechCorp portal in your course environment, and any target for which you hold explicit written authorization. You may not test: any other student's instance, the college's systems or network, your employer's systems without written authorization, classmates' machines, or any public website.

You do not run an automated scanner (such as ZAP, Nessus, or Burp) against your environment or anyone else's. Google's Cloud Shell terms of service prohibit network scanning. In Module 07 you read the supplied testing evidence packet, judge its findings, and compare the tools. This course build uses a clearly labeled simulated packet. You confirm your own fixes by hand: you send a test input to your own environment and watch it fail after your fix.

Running the lab safely

  • Sign in to your environment. Launch it from the Launch Course Environment page and sign in with one of the demo accounts listed there. Everything you need, including the editor, is there.
  • Use throwaway credentials only. Never put a real password, real personal data, or anything from work into the portal, and never reuse the portal's demo passwords anywhere else.
  • Test only your own environment. Your copy is yours to break and repair. Do not point any test, payload, or tool at another student's environment or at any system you do not own.
  • Reset when you need to. Your instance can be reset to its starting state; Module 01 shows how, so you can never break the data beyond repair.
  • You do patch this application. The portal is your environment and your codebase. Nearly every module brings a TechCorp incident against a feature: you write the incident report and fix the code in the editor, and your lab evidence is the exploit working before your fix and failing after it.

If you are ever unsure whether a target is in scope, the answer is no. Ask me first.
