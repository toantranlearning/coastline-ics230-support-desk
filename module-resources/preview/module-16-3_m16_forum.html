One real incident whose root cause is this module's topic. Say what went wrong and how it could have been stopped, then engage a classmate. The deep analysis belongs in your incident report.

The incident

In September 2025 a self-replicating worm, publicly named Shai-Hulud, spread through the npm package registry. That registry is where JavaScript projects download their dependencies. The worm began with compromised maintainer accounts. Unit 42 reports the likely start as a phishing campaign that imitated npm and asked developers to update their sign-in options. The attacker published new versions of the packages those maintainers owned. Each new version carried a post-installation script. When a developer or a build server installed one, the script ran and searched the machine for secrets: npm tokens, GitHub personal access tokens, and cloud API keys. It sent them to the attacker and published them to a public GitHub repository named Shai-Hulud under the victim's own account. Then it used the stolen npm token to sign in as that developer, find their other packages, inject the same code, and publish new versions. Every install of an infected version produced new infected packages. The attacker did nothing further.

The facts, from the primary report, the registry's owner, and the government alert:

  • GitHub says it was notified of the attack on September 14, 2025. It removed more than 500 compromised packages from the registry.
  • CISA's alert of September 23, 2025 puts the count at over 500 packages. It describes the same mechanism: credential harvesting, exfiltration, and automated republishing as the compromised developer.
  • Unit 42 says the worm ran as a post-installation script and spread through stolen npm tokens. It calls the phishing origin likely, not confirmed.
  • No CVE number exists for this incident. No package had a flaw in its code. The registry served exactly the versions the attacker published.
  • GitHub's response includes removing legacy publishing tokens, moving maintainers to phishing-resistant two-factor authentication, and shortening the life of publishing tokens.

Sources: Unit 42's analysis of the Shai-Hulud attack (opens in a new tab), GitHub's statement on npm supply chain security (opens in a new tab), and CISA's alert on the npm compromise (opens in a new tab).

Nobody found a bug in a library. A build pulled the newest version of a package it did not pin. It ran a script nobody had reviewed. It handed over the credentials that let the next package be poisoned. The chain in lecture section 2 is this incident, one link at a time.

Initial post

Write 150 to 250 words answering both questions about the Shai-Hulud incident, in this module's vocabulary:

  1. What did they do wrong? Trace the failure as a chain. Name the source of the code a build ran (the registry entry the attacker controlled), the trust boundary it crossed into the developer's machine, and the sink where it ran (the install step). Say what the harvested secrets then let the attacker do. Name the lecture's recurring conditions that were present, and say why each one was survivable on its own. "npm got hacked" is a headline, not an analysis.
  2. How could it have been prevented? Name at least one specific control at a specific link. Say whether it is preventive, detective, limiting, or recovery. A pinned version in a committed lock file, phishing-resistant two-factor authentication on the maintainer account, a short-lived publishing token, and an alert on a new public repository are all fair game. Then say why your control stops this exact chain rather than attacks in general.

A strong post names the mechanism, not only the headline.

Peer reply

Reply directly to at least one classmate, in at least 75 words. Open with their name and sign yours. Stress-test their prevention: would their control have stopped this exact chain, or only the first link they thought of? A control that stops the phish does nothing for the infected versions already in the registry. Then add one control at a different link, so the two of you have sketched defense in depth. Post early enough in the module for a real exchange.

Expectations

Full sentences, proper grammar and punctuation, no text-message shorthand. "I agree" is not a reply.
