What this module is for

Module 01 named confidentiality and integrity as two of the three security objectives. This module is about the tools that enforce them on stored data, and about using those tools without inventing anything: start from the property the data needs, then pick the trusted primitive that provides it.

Hashing, encoding, and encryption are three different jobs. A hash checks a value and has no way back. Encoding is a change of spelling that anyone reverses. Encryption hides a value from anyone without the key, and the key brings it back. Most real cryptographic failures are a correct algorithm used for the wrong job, a key in source control, or encryption with no integrity check.

This module's incident, TC-IR-009, is the customer tax identifier. It is stored exactly as it was typed, so the copy of the database that left in the pre-term breach holds every identifier readable. It is printed on two pages when one workflow needs it. You restrict where it is shown, encrypt it at rest with authenticated encryption, set the key in your environment, and convert the rows already in the file.

The question this module answers

Which cryptographic property does this data need, and how do you use a trusted primitive to provide it without inventing a protocol?

What you will be able to do

After Module 10 you can:

  1. Tell a hash, an encoding, and encryption apart by what each one does and does not provide.
  2. Name the property a value needs before choosing a primitive, and say what the choice does not protect against.
  3. Explain why encryption without authentication accepts tampered data silently, and what authenticated encryption adds.
  4. Seal a value with the course library, bind it to its row, and open it only on the page that needs it.
  5. Keep the key in the environment and out of source control, and restart the portal so it sees the key.
  6. Convert stored plaintext to ciphertext with a one-time migration that is safe to run twice.
  7. Choose between an HMAC and a digital signature, and generate tokens and keys an attacker cannot predict.

Before you start

  • Reread Module 01 lecture section 3 if confidentiality and integrity are not yet automatic. This module is the machinery that enforces them on data at rest.
  • Reread Module 08 lecture section 6, deny by default. Deciding which page may show a field is that rule applied to a field.
  • Passwords are not this module's subject. Module 09 lecture section 3 taught how they are stored; this module says so in one sentence and moves on.
  • Sign in to your course environment as rmarsh, open any account from the customer search, and find the Tax ID row. You will see where the value is shown before you change where it is kept.

Materials

  • The lecture page, which teaches everything the quiz and the assignment need.
  • OWASP Top 10:2025 A04 Cryptographic Failures and the OWASP Cryptographic Storage Cheat Sheet, the two required readings.
  • customer.php and admin.php, the two pages that print the tax identifier. lib/crypto.php, the course library's enc_seal and enc_open. data/seed.sql, where the seeded rows come from. scripts/start.sh, which loads your key.
  • The TC-IR-01 Form and Worked Example page in the Course Orientation module.

Where you may run this

You change code this module, in your own course environment. There is no scanning and no attack tool; the only test is a request you type at your own portal. Use only the portal's seeded data. Never put a real tax identifier or any other real personal data into your environment. Never put your key in a file Git tracks.

When you are done

Module 10 is complete when you have submitted the quiz and the incident report for TC-IR-009. The report is the completed TC-IR-01 form: the property and the weakness named in section 5, the tax identifier shown only on the admin audit table, the tax_id column holding ciphertext after a one-time migration, and the key in .env and nowhere else. Section 7 holds the before-and-after evidence: a tampered row releases nothing, and the audit table still shows every identifier correctly.
