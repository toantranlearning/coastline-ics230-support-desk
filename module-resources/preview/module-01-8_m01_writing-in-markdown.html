Use this page to prepare and submit the supplied report. Cloud Shell is where you change code and run tests. Word or Word Online is where you complete the report.

1Download and save your report

  1. Open the module assignment in Canvas.
  2. Select Download the accessible Word report template.
  3. Open the downloaded .docx in Word. If using Word Online, upload it to your document storage and open it there.
  4. Choose Save As or Save a Copy and use the filename in the assignment, such as m02-design-audit.docx.
  5. Keep the file in a place you can find again. Word templates are not in the student code repository, and Cloud Shell Editor does not edit them.

2Read the model before writing

The report already contains TechCorp’s executive summary, case background, organizational roles, approved response, and management decisions. These sections show how a professional explains technical work to business readers. You are not expected to invent another corporate history or rewrite the supplied report.

Find the [STUDENT] entries. Each includes an EXAMPLE that demonstrates the expected type and length of answer. Keep both the prompt and example, then write your own response after Answer:. An expected outcome is not evidence: enter what your own test actually returned, even when it differs.

EXAMPLE — expected form: “The working portal returned 403 Forbidden for the database path; the signed-in Customers page still opened.” Your answer must reflect your own observations.

Modules 1–2 provide exact actions and ask for brief additions. Module 3 includes a few small choices and more explanation. The assignment defines how much analysis you need; the supplied corporate narrative does not add unlisted work.

3Add command output and screenshots

  1. Run the assigned command or browser test in your own portal copy.
  2. Copy the actual command and output from Cloud Shell. Paste them into the matching report entry as selectable text.
  3. Capture the required screenshot and save it with the assignment’s filename.
  4. Click the screenshot entry in Word, choose Insert → Pictures, and select your image. Use In Line with Text so the picture stays with its paragraph.
  5. Add a short caption explaining the portal, input, and visible result. Add descriptive Alt Text to the picture. Follow the EXAMPLE supplied with that entry.
  6. Resize the image proportionally so it fits the page and its important details remain readable. Do not replace command output with a screenshot when exact text is requested.

A screenshot embedded in the Word report travels with that .docx. A typed filename alone does not embed the image. Upload separate image files only when the assignment requests them or when you reference images that you have not embedded.

4Explain the business impact

Read the supplied impact assessment and likelihood–impact matrix. In the marked entry, confirm or revise the initial ratings, explain why the condition matters, and connect the repair to reduced harm or likelihood. Use the supplied EXAMPLE as a model of reasoning, not a statement that your tests passed. Module 1 addresses setup reliability; it does not require a discovered vulnerability.

5Complete Revision History

At the end of the report, keep TechCorp’s initial version entry. Complete the next revision row with your actual date, name, and a concise description of your contribution. Each requested field has an EXAMPLE.

EXAMPLE — change summary: “Added direct-access findings, router verification, screenshots, and the revised risk assessment.” This records your changes to the document; the changed source files separately record your implementation.

6Check the document

  1. Keep the supplied Title and heading styles. Use Word’s heading styles for any added sections.
  2. Keep the table header rows and the supplied report structure. Let tables and answer spaces expand as needed.
  3. Confirm that every required answer, test, disclosure, screenshot, and revision entry is present.
  4. In Word, run Review → Check Accessibility and address its findings. Make sure pictures have alt text and headings are in order.
  5. Save the completed .docx. Reopen it to check that its text, tables, and images remain readable. If working online, download the completed Word file for Canvas.

7Submit the report and code together

For a code-repair assignment, submit these parts in the same Canvas attempt:

7. Submit the report and code together. Columns: Part, What to submit.
PartWhat to submit
ReportYour completed .docx, including embedded evidence and Revision History
InstructionsThe supplied assignment.md, unchanged
ImplementationEvery complete changed source file named by the assignment; a snippet in Word does not replace a source file
  1. In Cloud Shell Editor, find assignments/module-XX/assignment.md for the module. Right-click it and choose Download.
  2. Download each required changed file from fixed/ in the same way. Module 1 requires both edited PHP files downloaded before restoring the practice labels.
  3. In Canvas, choose Start Assignment or New Attempt and upload the report, assignment.md, and required source files. Add separate evidence files only as directed.
  4. Select Submit Assignment. Check the confirmation and upload list. A saved Word file or Cloud Shell edit is not a Canvas submission.

What assignment.md is for

assignment.md is a Markdown text copy of the task instructions. It mirrors the activity naturally, with descriptions of instructional images. Leave it unchanged and include it with your submission. You can read it in Cloud Shell Editor; you do not write your incident report in it.

A special assessment or design project can specify another submission format. Follow that page’s explicit requirements and assistance rules.
