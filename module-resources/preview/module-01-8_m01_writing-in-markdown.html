An .md file is a Markdown document. It is an ordinary text file with simple marks for headings, lists, links, tables, and code. For example, ## Evidence becomes a section heading in a Markdown preview. You can still read and edit the original file as plain text.

★The file and its preview are two views of the same document

In the editor, you write **important**. In the preview, you see important in bold. The saved .md file contains the marks; the preview displays their formatting. Markdown is useful here because your explanation, code excerpts, and observed output can live together in one readable report.

How this course uses Markdown

  • Incident reports and lab write-ups: edit .md files and upload them with the attachments the assignment requests.
  • Report starters: copy the assigned file from assignments/incident-reports/ into reports/, then add your observations, analysis, and verification. You can also download the starter from the Canvas assignment.
  • Repository instructions: files such as README.md explain how to use the lab and its resources.
  • Source code: your repair remains in .php files. Putting PHP in a report's code block describes the repair; it does not update the application.
  • Team design documents: follow the project's shared-document and PDF instructions. The assignment specifies its submission format.

iSave the actual Markdown file

Upload the .md file, rather than a screenshot of the editor, so the instructor can read and assess the full report. Evidence screenshots are separate attachments when required. Check the filename ends in .md, not .md.txt.

Make your first report

  1. Open the course repository in the Cloud Shell editor and find the assigned starter under assignments/incident-reports/.
  2. Copy it into reports/. For Module 03, name your copy m03-tc-ir-002.md.
  3. Replace bracketed prompts such as [Your name] with your own work. Keep supplied case facts distinct from findings you observed.
  4. Save the file and open the editor's Markdown preview. If the preview control is unfamiliar, search the command palette for “Markdown preview.”
  5. Compare the editor and preview: headings should be headings, and output should remain in code blocks. Fix formatting before submission so the evidence is easy to follow.
  6. Download your completed file from Cloud Shell and upload it to the Canvas assignment with any required evidence files. Keep a separate copy because the lab is a working environment, not an archive.

The examples below show the marks you will use most often.

Where your reports live

Your portal copy has a reports/ folder for your write-ups. Completed reports are ignored by Git. Keep your Canvas submission and a separate copy; do not rely on reset or fresh-clone behavior for preservation. Name each file for what it covers, for example tc-ir-002.md. To create one, right-click the reports folder in the file list and choose New File.

The marks

Each example shows what you type on the left and what it becomes on the right.

Headings

MARKDOWN
# Incident report TC-IR-002
## 2. Executive summary
### Detail

One # is the title, ## a section, ### a subsection. Put a space after the marks. The TC-IR-01 form's section numbers are headings.

Paragraphs and bold

MARKDOWN
A paragraph is a block of text. Leave a blank line between paragraphs.

The **source** is the search term in the query string.

Two asterisks around a phrase make it bold. Use bold for the terms an assignment asks you to name, so a reader finds them.

Lists

MARKDOWN
- the search term
- the customer name

1. Reproduce it.
2. Trace the flow.
3. Fix it.

A hyphen and a space starts a bulleted item. A number, a period, and a space starts a numbered one.

Links

MARKDOWN
[OWASP Input Validation Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Input_Validation_Cheat_Sheet.html)

The text in square brackets is what the reader sees; the address in parentheses is where it goes. This is how you cite a source.

Code in a sentence

MARKDOWN
The value enters at `$_GET['q']` on line 21.

Single backticks around a file name, a variable, a function, or a command set it in a code font so it reads as code.

A block of code or output

A line of three backticks opens a block and another line of three closes it. The backtick key is usually above Tab. Put the language right after the opening backticks so the block is colored: php, html, sql, bash, or text for output. In the example, type three backtick characters where it says (three backticks).

(three backticks)php
$q = trim($_GET['q'] ?? '');
(three backticks)

(three backticks)text
HTTP/1.1 400 Bad Request
(three backticks)

The first block renders as colored PHP and the second as plain output. This is how evidence goes into a report: the command you ran and the response you got, each in its own block.

Tables

MARKDOWN
| Check | Before | After |
|---|---|---|
| Search for `Test` | name shown in bold | name shown as text |
| Search for `Brien` | one result | one result |

The first row is the header. The second row, hyphens between pipes, separates it from the data. Each pipe starts a cell.

An image

Where evidence is a screenshot, save the image file next to the report and reference it:

MARKDOWN
![Search results after the fix, showing the literal name](tc-ir-002-after.png)

Upload the image file with the report. The text in the square brackets describes the picture for a reader who cannot see it.

Previewing as you write

  1. Open the .md file in the editor.
  2. Press Ctrl+Shift+V (Cmd+Shift+V on a Mac). A preview opens showing the rendered page. Ctrl+K V opens it beside the file instead, so you can see both.
  3. The preview updates as you type. If a heading is not a heading, check for the space after the #. If a code block runs to the end of the file, a closing fence is missing.

Starting a report

Every incident report starts with this block, filled in:

NAME: First Last
AI DISCLOSURE: What you asked an AI and what you used, or "None."
REFLECTION: Two or three sentences: what you fixed, what was
difficult, and what you learned.

Then the form's sections as ## headings, in order, with the content each assignment asks for.

Getting the file out of Cloud Shell

  1. In the file list, right-click the report file.
  2. Choose Download. The browser saves it to your computer.
  3. Do the same for each image the report references.
  4. Upload the files to the Canvas assignment.

Troubleshooting

  • The preview shows # characters. Add a space between the # and the heading text.
  • A list runs together as one paragraph. Put a blank line before the first item.
  • Code shows as ordinary text. The opening fence needs three backticks on their own line, and the closing fence too.
  • Download is not in the menu. Right-click the file itself, not the editor tab.
