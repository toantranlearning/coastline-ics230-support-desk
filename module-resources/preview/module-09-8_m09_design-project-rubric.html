Design Project Expectations and Evidence

The project uses the shared Assignment Rubric in Canvas. Its draft, team final, and individual build/decision submission are each worth 100 points, and count equally within the Assignments category (40% of the final course grade). These project expectations explain what the rubric assesses; they are not a separate native rubric.

Apply the shared rubric to each submission

For the draft, submit the assembled design, honest attribution, current build evidence, and unresolved questions required by the assignment. For the team final, show a requirements-grounded threat model, specific safeguards, agreement across authentication, authorization/data, and operations, and a verification plan with requests and expected results. For the individual submission, show your own running required core, actual request/response evidence, and your unaided decision under challenge. Team scores assess team deliverables; individual scores assess the student's own work.

Required safeguard evidence

A safeguard earns credit under the shared Assignment Rubric only when the evidence shows it working. Each category the project builds gets one row: the safeguard, and the curl result that proves it. The required core is graded for every project; the electives are graded only where the design chose to build them.

Required safeguard evidence. Columns: Category, Safeguard, Evidence that proves it.
CategorySafeguardEvidence that proves it
Authentication (required)API-key authenticationA request with no key returns 401; a valid key in the header returns 200.
Object-level authorization (required)Ownership check on every objectThe owner gets 200; a non-owner requesting the same object gets 403 or 404.
Input validation (required)Allow-list of fields, checked types and rangesAn unknown or oversized field returns 400; malformed JSON returns 400.
Error output (required)Errors that leak nothingA forced failure returns a short message with a correlation id, and no stack trace, SQL text, or file path.
Delegated access (required core)Key exchanged for a scoped, expiring tokenA valid key trades for a scoped token; an altered or expired token returns 401.
Rate limiting (elective)Per-caller request capRequests past the cap return 429 with a Retry-After header.
Pagination caps (elective)Bounded page sizeA page size above the cap is clamped, never unbounded.
Audit log (elective)Append-only record of billing changesA billing change writes one row that the caller cannot edit.
Callback handling (elective)Destination allow-list against SSRFA callback URL pointed at a private or link-local address is rejected before any request is sent.
CORS policy (elective)Explicit trusted originsAn allowed origin is echoed; another is not; * is never sent with credentials.

What the attribution table is for

The attribution table, which member authored and built which part, is what makes the individual grade defensible. A member who authored nothing and built nothing has nothing of their own to be graded on under the shared Assignment Rubric.
