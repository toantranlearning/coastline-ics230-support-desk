One real incident whose root cause is this module's topic. Say what went wrong and how it could have been stopped, then engage a classmate. The deep analysis belongs in your incident report.

The incident

In April 2025, SAP fixed an unrestricted file upload flaw in SAP NetWeaver. NetWeaver is the Java platform under many of the business systems that run factories, payroll, and supply chains. The flaw, CVE-2025-31324, sat in a component called the Visual Composer Metadata Uploader. Its upload endpoint took a POST from anyone on the internet, with no sign-in and no check on what the file was. Attackers posted JSP files, the Java equivalent of a .php page. The server wrote them into a folder it both served and ran code from, and a plain GET request for the new file then ran it. Responders found such files on systems that had every patch available at the time.

The facts, from the CVE record and two reports:

  • Affected: SAP NetWeaver Visual Composer Framework 7.50. SAP, which assigned the CVE, says the uploader was "not protected with a proper authorization," so a caller who never signed in could upload executable files. Fixed by SAP Security Note 3594142, released April 24, 2025, outside the normal patch cycle.
  • Weakness: CWE-434, unrestricted upload of file with dangerous type. SAP scored it CVSS 10.0; NVD scored it 9.8.
  • ReliaQuest reported the attacks on April 22, 2025. It found the uploaded JSP files in a folder the application server serves, and said they could be run "through simple GET requests." Onapsis also reported attacks in progress.
  • SAP's statement, reported by BleepingComputer, was that it was "not aware that SAP customer data or systems were impacted." The attack findings are the researchers' claims, not SAP's.
  • CISA added the CVE to its list of known exploited flaws on April 29, 2025.

Sources: the CVE record for CVE-2025-31324 (opens in a new tab), ReliaQuest's report (opens in a new tab), Onapsis's advisory (opens in a new tab), and BleepingComputer's report (opens in a new tab).

Nobody guessed a password or broke a cipher. Bytes the sender chose were written to disk in a folder the server runs code from, and the server ran them when asked. The interpreter is a Java servlet engine instead of the PHP engine in the lecture; the flow is the same.

Initial post

Write 150 to 250 words answering both questions about the SAP NetWeaver incident, in this module's vocabulary:

  1. What did they do wrong? Trace the failure as an upload flow: name the source the attacker controlled, the trust boundary the bytes crossed, the sink they reached, and the interpreter on the far side. Say which of the lecture's upload controls were missing. Be precise about why an unchecked file in a served, executable folder turned an upload into remote code execution.
  2. How could it have been prevented? Name at least one specific control at a specific point in that flow, and say why it stops this exact attack rather than attacks in general. Fair game: a sign-in check on the endpoint, a content check against an allow-list of detected types, a server-generated name, or storage outside the web root.

A strong post names the mechanism, not only the headline.

Peer reply

Reply directly to at least one classmate, in at least 75 words. Open with their name and sign yours. Stress-test their prevention: would their control have stopped this exact web shell, or only the uploads they thought of? Then add one control at a different point in the flow, so the two of you have sketched defense in depth. Post early enough in the module for a real exchange.
