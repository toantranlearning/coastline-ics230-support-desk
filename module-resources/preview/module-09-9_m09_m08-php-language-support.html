A training equipment application has two users. Alex owns a camera booking; Morgan owns a tripod booking. Both can sign in. When Morgan requests Alex's booking number, the PHP program needs to recognize Morgan and refuse access to the other booking. A valid identifier alone is not that decision.

The security lecture teaches authentication, authorization, ownership, and API access. This companion explains how to read the PHP statements that express those decisions. The examples use bookings rather than the incident assignment's customer and staff-console repairs.

★Trace the actor and object separately

The session or API credential identifies the caller. The requested identifier selects an object. A policy must connect those two values before protected information is returned or changed.

1Select entries from a server-side actor array

An associative array connects named keys to values. => connects a key and value when building the array; square brackets select an entry afterward.

PHP
<?php
$actor = ['id' => 7, 'role' => 'member', 'disabled' => false];
echo $actor['id'] . "\n";
echo $actor['role'] . "\n";
var_dump($actor['disabled']);
Output
7
member
bool(false)

$actor['id'] is the integer 7. $actor['role'] is text. $actor['disabled'] is a Boolean. echo writes values; var_dump also exposes their type. . joins output text, and "\n" adds a line break.

A web application calls session_start() to open or resume a session, then reads $_SESSION. A value such as $_SESSION['user_id'] is meaningful only if the sign-in code established it using the verified account record. Calling session_start alone does not authenticate a user.

Question: Is a requester-supplied $_COOKIE['role'] the same as the server's session role? No. A cookie is client-supplied data. A correctly established server-side session can carry the trusted account role. The browser normally carries only the session identifier used to locate that session.

Source: PHP session variables (opens in a new tab) describes $_SESSION.

2Recognize missing values and strict comparisons

✓PHPSecure
<?php
// WHY: A missing role must not acquire permission from a default that grants access.
$session = ['user_id' => 7];
$role = $session['role'] ?? null;
var_dump($role);
var_dump($role === 'admin');
var_dump(7 === '7');

Secure. Why: A missing role must not acquire permission from a default that grants access.

Output
NULL
bool(false)
bool(false)

?? chooses the right-hand default if the key is missing or null. It does not check whether an existing value is a valid role. === compares value and type; the integer 7 and string '7' are not identical. !== tests the opposite.

An identifier read from a URL commonly begins as a string. A database driver may return an integer for a numeric column. Validate and normalize identifiers deliberately before comparing them; do not replace strict comparison with loose equality to hide inconsistent types.

! means NOT, && means both conditions must be true, and || means at least one must be true. Short-circuit evaluation can protect a later lookup: in $object !== null && $actor['id'] === $object['owner_id'], the key lookup is skipped when the object is null.

Source: PHP comparison operators (opens in a new tab) explains identity comparisons.

3Read a policy function and its return value

✓PHPSecure
<?php
// WHY: Only an explicitly permitted action returns true; unknown actions stay denied.
function may_view(string $action, array $actor, ?array $booking = null): bool
{
    if ($actor['disabled']) {
        return false;
    }
    switch ($action) {
        case 'booking.read':
            return $booking !== null && $actor['id'] === $booking['owner_id'];
        case 'inventory.list':
            return true;
        default:
            return false;
    }
}
$alex = ['id' => 7, 'disabled' => false];
$morgan = ['id' => 8, 'disabled' => false];
$booking = ['id' => 41, 'owner_id' => 7];
var_dump(may_view('booking.read', $alex, $booking));
var_dump(may_view('booking.read', $morgan, $booking));
var_dump(may_view('booking.archive', $alex, $booking));

Secure. Why: Only an explicitly permitted action returns true; unknown actions stay denied.

Output
bool(true)
bool(false)
bool(false)

function declares the operation. string $action expects an action string; array $actor expects actor data; ?array $booking = null accepts either an array or null and supplies null when omitted. : bool declares a Boolean return value.

return ends the current function call and sends its value back. It does not automatically stop the web request. The calling route must use the result in a branch and stop on refusal before loading or changing protected data.

switch selects a matching case. Because each case returns, no break is needed here. The default covers actions with no explicit rule. Alex owns the booking; Morgan does not; neither user receives an archive permission that was never defined.

!The function cannot establish its own trusted inputs

Passing an actor assembled from a submitted role field defeats a correct policy function. Build the actor from verified server-side identity because a policy can only evaluate the values it receives.

Source: PHP user-defined functions (opens in a new tab) explains parameters and declarations.

4Express a role permission list

✓PHPSecure
<?php
// WHY: Strict membership in a developer-written permission list denies unmapped roles and actions.
$permissions = [
    'member' => ['booking.read'],
    'manager' => ['booking.read', 'inventory.edit'],
];
function has_permission(string $role, string $permission, array $map): bool
{
    return in_array($permission, $map[$role] ?? [], true);
}
var_dump(has_permission('manager', 'inventory.edit', $permissions));
var_dump(has_permission('member', 'inventory.edit', $permissions));
var_dump(has_permission('unknown', 'booking.read', $permissions));

Secure. Why: Strict membership in a developer-written permission list denies unmapped roles and actions.

Output
bool(true)
bool(false)
bool(false)

in_array receives the value sought, the array searched, and a strict-comparison switch. The third argument true prevents a type-converting membership comparison. An unknown role receives an empty list through ?? [], so membership returns false.

This role check answers whether a role has a feature permission. It does not answer whether the caller owns a particular booking. Those are separate policy inputs.

Source: PHP in_array (opens in a new tab) documents the strict argument.

5Combine attributes and time conditions

✓PHPSecure
<?php
// WHY: All stated conditions must hold before a booking can be approved.
function may_approve(array $actor, array $booking, int $now): bool
{
    return $actor['role'] === 'manager'
        && $actor['location'] === $booking['location']
        && $booking['status'] === 'pending'
        && $now < $booking['deadline'];
}
$actor = ['role' => 'manager', 'location' => 'North'];
$booking = ['location' => 'North', 'status' => 'pending', 'deadline' => 2_000];
var_dump(may_approve($actor, $booking, 1_999));
var_dump(may_approve($actor, $booking, 2_000));

Secure. Why: All stated conditions must hold before a booking can be approved.

Output
bool(true)
bool(false)

The line breaks do not change the expression. All four conditions are connected by &&. The final < means strictly before the deadline; equality is denied. Numeric underscores improve readability without changing the number: 2_000 is 2000. In a real handler, time() can supply the current Unix timestamp. All compared timestamps must use the same units.

6Read an ownership-filtered query

The portal's q_one($sql, $parameters) returns one associative row or null. q_all returns all result rows, possibly an empty array. q returns an executed PDO statement. Their definitions in lib/query.php use prepared statements; request-derived values belong in the parameter array.

This standalone database shows the shape on equipment bookings, using direct PDO rather than the portal helpers.

✓PHPSecure
<?php
// WHY: Filtering by both requested id and verified actor id prevents another owner's row from being returned.
$pdo = new PDO('sqlite::memory:');
$pdo->setAttribute(PDO::ATTR_DEFAULT_FETCH_MODE, PDO::FETCH_ASSOC);
$pdo->exec('CREATE TABLE bookings (id INTEGER, owner_id INTEGER, label TEXT)');
$insert = $pdo->prepare('INSERT INTO bookings VALUES (?, ?, ?)');
$insert->execute([41, 7, 'Camera']);
$statement = $pdo->prepare('SELECT label FROM bookings WHERE id = ? AND owner_id = ?');
$statement->execute([41, 8]);
var_dump($statement->fetch());
$statement->execute([41, 7]);
echo $statement->fetch()['label'] . "\n";

Secure. Why: Filtering by both requested id and verified actor id prevents another owner's row from being returned.

Output
bool(false)
Camera

The first array element binds to the first ?, the booking identifier. The second binds to the second ?, the actor identifier. Morgan's request finds no matching row. Alex's request finds the booking.

PDO fetch() returns false for no row; the course q_one wrapper converts that to null. The successful second lookup returns an array, and ['label'] selects its label. The query also needs the right policy for administrators and other relationships; ownership is this example's chosen rule.

require_once __DIR__ . '/lib/query.php'; loads the helpers once. The path depends on the current source file location: an API file inside api/ usually needs the appropriate parent-directory path. __DIR__ names the current file's directory, not the browser URL.

iBinding and permission solve different questions

Prepared statements keep values from rewriting SQL. The owner_id predicate limits which rows the identified caller can receive. Omitting that predicate can leave an IDOR even when every value is bound.

Source: PHP PDOStatement::fetch (opens in a new tab) describes the direct PDO result.

7Read request method, path, and a redirect choice

PHP exposes request metadata through $_SERVER. $_SERVER['REQUEST_METHOD'] commonly contains a string such as GET or POST. PATH_INFO depends on routing and server configuration; it is not guaranteed on every request. REQUEST_URI commonly contains the requested URI, including a query string.

PHP
<?php
$server = ['REQUEST_METHOD' => 'GET', 'REQUEST_URI' => '/bookings/41?view=brief'];
$method = $server['REQUEST_METHOD'] ?? '';
$path = parse_url($server['REQUEST_URI'], PHP_URL_PATH);
echo $method . "\n";
echo $path . "\n";
Output
GET
/bookings/41

The simulated array makes the example runnable without a server. parse_url with PHP_URL_PATH extracts the path portion. It can fail or return a missing component for other inputs, so real routing validates the result. Extracting a path does not authorize the resource named by that path.

For a redirect, the same mapping pattern used for roles can choose an allowed destination: ['home' => '/index.php', 'bookings' => '/bookings.php']. The request supplies a key; the application supplies the path. header('Location: ' . $location) sends that destination, and exit stops further statements. Without exit, PHP continues processing even if a browser follows the redirect.

Sources: PHP server variables (opens in a new tab) and PHP parse_url (opens in a new tab) explain these inputs and extraction results.

8Build a JSON response deliberately

✓PHPSecure
<?php
// WHY: JSON serialization preserves the object structure instead of building a response by concatenating requester text.
$body = ['booking_id' => 41, 'label' => 'Camera', 'approved' => false];
echo json_encode($body, JSON_THROW_ON_ERROR) . "\n";

Secure. Why: JSON serialization preserves the object structure instead of building a response by concatenating requester text.

Output
{"booking_id":41,"label":"Camera","approved":false}

json_encode takes a PHP value and returns JSON text. Named array keys become JSON object properties in this example; the Boolean stays a Boolean. JSON_THROW_ON_ERROR requests an exception when encoding fails, avoiding a silently false result. It does not filter which fields the caller may see: select the permitted response fields first.

A web response also uses http_response_code(404) and header('Content-Type: application/json'). Those operations select a status and body type; they do not print the JSON or stop execution. Set them before output, write the body, then stop when the route has completed. A 401 response is an authentication failure; a known caller refused by policy commonly receives 403. Some object endpoints deliberately use the same 404 for forbidden and missing objects to limit enumeration.

Question: Does a JSON content type mean the response contains no private data? No. Serialization and disclosure policy are separate decisions.

Source: PHP json_encode (opens in a new tab) documents serialization and error flags.

9Read an API key from a header and hash it

A request header named X-API-Key is commonly exposed as $_SERVER['HTTP_X_API_KEY']: uppercase letters, underscores in place of hyphens, and an HTTP_ prefix. Exact server behavior still depends on the deployment. Validate the supplied value as a string before using string functions.

✓PHPSecure
<?php
// WHY: Securely generated keys are unpredictable, and storing a digest avoids retaining the usable credential in the key table.
$key = bin2hex(random_bytes(32));
$digest = hash('sha256', $key);
echo strlen($key) . "\n";
echo strlen($digest) . "\n";
var_dump(hash_equals($digest, hash('sha256', $key)));

Secure. Why: Securely generated keys are unpredictable, and storing a digest avoids retaining the usable credential in the key table.

Output
64
64
bool(true)

random_bytes(32) returns 32 random bytes. bin2hex converts them into 64 printable hexadecimal characters. hash('sha256', $key) returns a 64-character hexadecimal digest. The matching lengths do not imply that the two strings are the same value.

hash_equals($known, $supplied) returns a Boolean from timing-safe string comparison; trusted value first, supplied value second. It does not establish ownership or check whether the key is disabled. A query must separately select an eligible client, and later object queries must enforce that client's permitted data.

The lecture's indexed digest lookup may already compare the digest in the database. Adding hash_equals makes the application equality check explicit; it does not remove timing or enumeration behavior introduced elsewhere in the request. Avoid promises that one comparison makes an entire endpoint constant-time.

Sources: PHP random_bytes (opens in a new tab), PHP hash (opens in a new tab), and PHP hash_equals (opens in a new tab) define these operations.

What does a true policy result do by itself? It returns permission to the caller. The route still needs to apply it before serving or changing the object.

Can a safe query helper decide ownership automatically? No. Its SQL must include the appropriate authorization relationship.

Why check the list route as well as the detail route? A list can disclose the same protected objects through a different path. Every protected path needs the policy.

Does a disabled API key stop existing independently issued tokens? Not necessarily. Token validity and revocation require their own design; the later token module covers that distinction.

What evidence belongs in the incident report? Actual owner success and non-owner refusal from your permitted tests, with sensitive identifiers or credentials redacted. This companion's fixture outputs are examples, not observations from your repair.
